## 得失

- **得**：物件原語不限第一步、選擇器不靠目標推（寬），C++ 速度把這棵寬樹走完，增量都來自這裡。
- **否定結果**：只放寬 grid／cells 原語參數並加深到 4～5，增量 0，多出來的都是過擬合（深層 local_rule）。
- 速度：無物件時約 76 萬節點／秒，有物件時約 28 萬節點／秒（單執行緒）。

## 代定

- S1-1 混合入口：主線先跑，主線無解才由 C++ 補；C++ 程式一律用 Python 重驗。
- S1-2 第一期增量 0 後轉向：移植 objects、物件原語任意深度、寬選擇器；種子＋前綴雙向接 Python；超過 4 步且以 local_rule 收尾的丟掉。
- S1-3 主線評測規則改了（不用排時段、workers ≤6、MemoryMax=8G），全量照新規則自己排、自己跑。
- S1-4 CUDA 先不做：瓶頸在表達力不在算力，GPU 不會帶來題數。

## 下一步（建議）

1. 新原語：照 icecuber 的思路加射線、連線、壓縮重複列欄、依顏色 crop、圖樣延續。Python 參考實作放 `native/` 之外的哪裡、怎麼註冊，要主線開介面（類似 S3 的一行 import）。這是能再往上的主要槓桿。
2. 過擬合：training 上 local_rule 深層解幾乎都錯，可加最小支持度或懲罰深度。
3. 主線 Python 一直在變（新 `m_sub_*` 巨集）。併入成績時由主線用最新 HEAD 重跑。
