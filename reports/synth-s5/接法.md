## 1. 重生

```sh
cd ~/repo/arcagi
systemd-run --user --scope -q -p MemoryMax=8G \
  nice -n 19 .venv/bin/python scripts/synth_generate.py --workers 6   # 約 5 秒
nice -n 19 .venv/bin/python scripts/synth_generate.py --check 20       # 重生 20 題比 sha256
```

- 產物 `data_synth/`（已 gitignore）：`training/<id>.json` 400 檔＋`manifest.json`。
- 每題 `train` ＝ **原 train pair（在前）＋ 24 個合成 pair**，`test` ＝原 test。官方格式（只有 `train`／`test` 鍵），`task_from_dict` 驗過。
- `manifest.json` 每題記 `n_original`（前幾個是原題）、`n_synth`、`seed`、`sha256`；整體記 re-arc revision、Python 版本、`PYTHONHASHSEED=0`、difficulty。
- seed：每題 `sha256("<seed>:<task_id>:<attempt>")`；預設 `--seed 0`、`--pairs 24`、`--min-pairs 20`、difficulty `0.0–0.5`。同 seed＋同 Python 版本＋同 vendor 檔 → 位元組相同（`--check` 驗過 20/20）。
- 只碰 training：re-arc 只有 training 的 400 條規則；evaluation 沒讀、也合成不了。

## 2. 接進產生器（主線做）

三台產生器都已經吃 `--data-root`，路徑解析 `<root>/data/training` 或 `<root>/training`，所以**不用改程式**：

```sh
uv run python -m arcagi.blocks.gen_formula    --split training --data-root data_synth [--dry-run]
uv run python -m arcagi.blocks.gen_predicates --split training --data-root data_synth [--dry-run]
uv run python -m arcagi.blocks.gen_extract    --split training --data-root data_synth [--dry-run]
uv run python -m arcagi.blocks.gen_meta       --data-root data_synth
```

效果：support 的定義（「在**每個** train pair 都成立」）不變，只是 pair 從 2～5 個變成 26～29 個，背答案的積木自然掉出去。

要注意的地方：

| 點 | 說明 | 建議 |
|---|---|---|
| 顏色／大小分布 | re-arc 會隨機換色、放大網格（例：3bd67248 背景從 0 換成 5）。綁死特定顏色的積木會被判掉，但 evaluation 的 test 跟自己的 train 同色，這類積木不一定真的沒用 | 看 [overfit 報告](README.md) 的「held-out 對照」欄；分數下降集中在綁色的就考慮只用合成集**降權**不**淘汰** |
| 耗時 | 每題 pair 多 ~8 倍，產生器評分時間約同比例變長（見 README 預覽秒數） | 先 `--dry-run` 量時間 |
| 軟門檻替代 | 嚴格「全部 pair 都過」可能太嚴 | 可改成「原 train 全過 且 合成 pair 過 ≥ X%」；`manifest.json` 的 `n_original` 讓你切 `train[:n]`／`train[n:]` |
| 求解器 | 合成集只給**產生器評分**用；搜尋求解仍跑原題 | `arcagi eval` 不要指到 `data_synth` |
| ledger | 本線不寫 `ledger.json` | 建議列見 README |

**建議先軟接**（理由與數字見 [README](README.md) §3–4）：嚴格換法會丟掉帳上有收入的 `formula_0832d6a3`、`extract_f23ec080`。
