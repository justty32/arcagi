## 5. 得失

**得**
- 量具到位：題組可重現（sha 9ce7c7ea…）、空樹可驗純淨、曲線確定可重跑、消融齊（noT、g1、dec、g1g4、old）；S1 的 `arcbatch` 給舊樹對照組節點預算快引擎（20 題 25k 節點 2.4 CPU 秒）。
- 第一次看到「不經 LLM 長積木」真的讓曲線動：壓縮出的積木被重用（`take 2` 多解 1 題、`map (λ sort)` 省 17 倍節點）。
- 守門把過 train 答錯砍到約三分之一，0 誤擋、evaluation 不退。

**失（否定結果）**
- 空樹 Δ 幾乎為 0、H8 0 題：16 題的解太少，壓縮與演化沒有料。**冷啟動是主瓶頸**，不是旋鈕。
- G4 演化在分解樹上 0 貢獻；meta 3 回合全部 Δ=0（Argon 預言的「整數顆粒太粗」成真）。
- 最大進步（2→4）來自 agent 手改優化器——這本身是「元優化流程」的一步，但不是自動的。

## 6. 下一輪方向（r08）

1. **解冷啟動**：(a) 題組外加「無答案練習池」——training 其餘 376 題只當 G1 的壓縮料（解出就抽、不計分），L16 仍是計分組；(b) 預算隨 pass 長大（迭代加深）讓深程式逐步出現；(c) S5 合成 pair 當額外 train 範例，減少過擬合解（44f52bb0 類）。
2. **補通用表達力**（A 線診斷給的清單，依便宜排序）：兩半各自求解拆法 → 巢狀 lambda／體深 3 → 二維位置拆法；每項都要過 purity。
3. **讓元優化有梯度**：主數字加連續量（解出題節點和、近解距離），旋鈕實驗用 4-pass×CRN；把「加一個拆法」也當成 meta 動作（由 agent 提案、曲線判、記 meta 帳），讓「改優化器」本身進遞迴。
4. **空樹語言 C++ 化**（S1，D-r7-6）：seed 運算式樹 JSON 已定，`arcbatch` 加通用語言模式。
5. 守門：剩 evaluation 10、training 20 題，多是 `stamp_key`、移動＋裁切、寫死顏色 `colormap`；把 families 的表也接進同一套自由度檢查；合成 pair 做顏色正規化後再當校準。
6. G2 re-arc 片段搬運、G3 殘差診斷仍延後（要先有判得出「片段 vs 整支 verifier」的工具）。
