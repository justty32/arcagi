## 1. 主軸換了：從「多解幾題」換成「長得多快」

使用者三句原話（經 aos 轉達，r07 一起做）：

- **元優化**（11-08 14:55）：「除此之外，我會希望arc agi這塊，把主要精力放在元優化。用於解決的訓練集只需要少少幾個就好，重點在於優化出能夠以最高效率最快解決問題的aos樹。途中可以繼續元優化這個元優化流程」
- **最終目標**（14:58）：「arc agi的題目以2d為主，但aos的優化卻是偏向於程式流程。兩者都可以用符號迴歸配合llm，最終目標是能夠從零開始，在對目標題目(arcagi)完全無認知的情況下，配合無神經網路的優化器，成長到能夠解決問題」
- **產積木不經 LLM**（14:51）：「關於產出積木這件事，是否可以不經過llm？」→「可以」。LLM 只當出題老師／對照組。

白話：以前比「400 題解幾題」；現在比「**一棵幾乎空的樹，給它 5～20 題 training，要幾輪、幾秒、幾個搜尋節點才全學會**」，而且要能改「學習的方法」讓曲線變陡，改「改學習方法的方法」也行。

## 2. 主指標與量法（隊長建議，規劃可改）

| 項 | 建議 |
|---|---|
| 主指標 | 小 training 題組的**學習曲線**：每輪（pass）一列 `pass, 解出題數, 牆鐘秒, 搜尋節點數, LLM 呼叫數(應為 0), 庫大小`；比較兩棵樹用「曲線下面積」或「到 k 題所需秒／節點」 |
| 起點 | **空基準**：不含 ARC 專屬手寫原語（不准 rot90、crop、objects、colormap 這類網格語意），只有通用基礎運算（序列／整數／布林／條件、map／filter／zip 這類通用高階函式）＋無神經網路優化器 |
| 一輪做什麼 | 用目前的庫在題組上搜尋（有節點／秒預算）→ 解出的程式交「長積木」步驟（壓縮、演化…）→ 庫長大 → 下一輪 |
| 防背答案 | 解出的程式要過原 train；能用 S5 合成集（`data_synth/`，re-arc 由 training 生）的就再驗合成 pair；題組外另留 holdout 小組只量不學；evaluation 偶爾量泛化 |
| 雜訊 | 枚舉確定 → 兩條基準多半一模一樣（arknights 第五輪也是 0）；有隨機的步驟（演化）要換 seed 跑兩條 |
| 防汙染 | 每次打基準 tag 前 `git diff --stat` 新樹與 `aos/blocks/`、`aos/pool/`，空基準樹不能混進學到的積木 |
| meta 帳 | 改樹本身的花費（秒、子 agent 次數）另記一本、只記不分紅（已有 `aos/meta/ledger.jsonl`） |
| 對照組 | r01～r06 手寫原語樹（`arcagi.solvers.search`、r06 混合入口 56/400）在同一題組的曲線（pass 0＝只原語、pass 1＝產生器跑完） |

## 3. 不可違反的約束

| 約束 | 說明 |
|---|---|
| 不用神經網路；不新增 Python 依賴 | 純 stdlib；可寫 C++／CUDA（另開資料夾，nvcc 在 /opt/cuda/bin，顯存 ≤12GB） |
| 機器 | `nice -n 19`、workers ≤12、單批 ≤16GB（`systemd-run --user --scope -p MemoryMax=16G`）、swap 只有 512MB；**全機同時一條全量評測**（S3 的 ev-dev1／sub-dev1 是別人的，等它結束）；小題組隨時可跑 |
| 人力 | 同時子 agent ≤3（opus 普通、sonnet 雜活）；每條線約 1 小時；不開 codex |
| 支線路徑不碰 | `native/`、`src/arcagi/dsl/ext/`（S1）、`src/arcagi/llm/`、`aos/llm/`（S2）、`src/arcagi/objrule/families/`（S3，**工作樹有它未 commit 的改動**）、`docs/taxonomy/`、`scripts/synth_*`、`scripts/taxonomy_*`；可唯讀呼叫 |
| 評分 | 成績以 evaluation 為準；產生／評分積木只用 training（含 S5 合成集） |
| 程式碼 | `src/arcagi/<領域>/`、單檔 >300 行拆、pytest 綠、commit 英文不 push |

- **r06 的元優化料**：空基準 blocks-root（暫存目錄＋`ARCAGI_POOL`）、雙折配對（`blocks/meta/`）、meta 帳、影子門檻 `python -m arcagi.shadow`、歸因 `scripts/attribution.py`、合成集軟接 `blocks/synth_score.py`。r06 結論：**固定語法旋鈕觸頂**（formula 7 設定全 0／負），要改結構不是調參數。
- **舊樹的求解器**：BFS 深度 3＋觀察等價去重＋終端學習器＋投票（`solvers/search.py`）；程式＝`[[原語名, 參數…], …]`（`dsl/program.py`）——是「原語串列」，不是運算式樹；原語都是手寫網格語意。
- **re-arc**（`vendor/re-arc/`）：`dsl.py` 約 160 個網格函式（ARC 專屬）、`verifiers.py`＝training 400 題的現成解答（**用了就是背答案**）、`generators.py`＝合成題來源（S5 已用）。
- **S5 合成集** `data_synth/training/`：每題 24 個合成 pair，`manifest.json` 的 `n_original` 分原題／合成。
- **S2 對照組**（`reports/llm-s2b/README.md`）：eval20 test exact 7/20、誤判 0；LLM 候選 73、live 8——LLM 當老師的基線。
- **S4 題型**（`reports/taxonomy-r04/README.md`、`docs/taxonomy/labels.csv`）：可拿來挑題組（分層取樣）。
- 機器：16 核、60GB RAM、RTX 5060 Ti 16GB。

## 5. 不經 LLM 長積木的候選（aos 建議先 1、2）

| # | 做法 | 說明 | 風險 |
|---|---|---|---|
| G1 | 庫學習／壓縮（DreamCoder wake-sleep 的 sleep 半） | 各題解出的程式抽共同子樹 → 新積木（帶槽）；同時學「哪個積木常用」的權重改搜尋順序 | 題組小時共同子樹少；要用 MDL（壓縮省的長度）而不是出現次數 |
| G2 | 從 re-arc 搬確定性程式 | 只能搬**通用片段**（verifiers 的子式）；整支 verifier＝training 正解 | 嚴防背答案：搬來的只准在 holdout／evaluation 量，或只搬 `dsl.py` 函式當「對照組樹」 |
| G3 | 殘差自動診斷 | 近失敗的程式輸出 vs 正解的差（尺寸錯、顏色錯、位置錯）分類 → 決定下一步搜哪類 | 分類器本身就是手寫知識，要算進「起點樹」 |
| G4 | 演化搜尋 | 程式樹變異／交配，適應度＝train 像素對率或帳本收益 | 有隨機源 → 要量雜訊；容易爆時間 |

## 6. 同時要收：「過 train 卻答錯」

r06 混合入口：evaluation Python 17＋native 12、training Python 30＋native 27（r05 為 14／26）。r06/04 §6 第 5 點：C++ 結果加投票或最小支持度、`stamp_key` 大表與 `x_vrule` 限制，用 S5 合成集判。

- 限制：`stamp_key` 在 S3 的 `objrule/families/`、`x_vrule` 在 S1 的 `dsl/ext/`、混合入口 `native/hybrid.py` 是 S1 的檔——主線**不改它們**，只能在主線求解器（`solvers/`）加通用守門（例：測試輸入出現 train 沒見過的鍵就不信這個程式、候選間投票、最小支持度），或在主線包一層入口。
- 判準：在 training 上，守門擋掉的「過 train 答錯」數 vs 誤擋的「本來答對」數；合成集可當額外驗證 pair 校準。
