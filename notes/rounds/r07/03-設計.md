## 1. 對規劃的調整（代定，見代定清單）

- **lambda 參數**（D-r7-2）：規劃寫「只有單參數」，但 `zipwith`、`fold` 要二元函式 → 允許 1～2 參數 lambda（de Bruijn `$0`、`$1`），體深度 ≤2 不變。
- **守門線離線優先**（D-r7-3）：C 線先用 r06 既有 artifacts（`artifacts/dsl-search-r06/training*.json(l)`、`evaluation*`）離線重算候選與守門，不重跑全量；真要重跑 training 全量（`solvers/gated.py` 入口），回報隊長排時段（S3 的 ev-dev1／sub-dev1 在跑）。
- **題組產生歸 B、但先做**（D-r7-4）：B 線第一件事產 `data/r07/taskset.json`；A 線在它出現前用任意 16 題 ≤15×15 training 自測，出現後改用 L16。
- **evaluation 不跑全量**（D-r7-5，同規劃）：機器空且 C 線做完才選跑一次 `gated` evaluation 當 r08 基線，不計門檻。
- **S1 介面回覆**（D-r7-6）：S1 第三任的 `native/bin/arcbatch`（題×設定、節點預算、白名單／macros）採為**舊樹對照組與舊樹旋鈕實驗**的快引擎；空樹在 C++ 端＝**現有原語全關**（它們全是 ARC 專屬），空樹的通用語言要 C++ 化排 r08（介面＝`seed/` 的運算式樹 JSON）。native 端的投票／最小支持度由 S1 自做，主線守門對 Python／native 候選一視同仁。

## 2. A↔B 介面（寫死，B 前 20 分鐘可 stub）

```python
# src/arcagi/seed/  (A 寫)
Program = tuple                      # ("op", *args) | ("$in",) | ("$0",) | ("$1",) | ("lam", n, body) | ("blk", name, *args) | int
seed.prims.PRIMS: dict[str, Prim]   # Prim(name, sig: Type, fn); ≤40
seed.types: Type 類（int/bool/list[T]/箭頭/型別變數）、unify
seed.interp.run(prog, x, lib) -> object        # 例外一律轉 seed.interp.EvalError；有步數上限
seed.enum.solve(train: list[(in,out)], lib: Library, budget_nodes: int, order: dict|None = None)
    -> Result(program|None, nodes: int, nodes_to_first: int|None, seconds: float, near: list[(program, score)])
seed.enumerate(lib, tasks: list[Task], budget_nodes, workers=1, order=None) -> list[Solution]
    # Solution: task_id, program, train_ok, test_ok, nodes, nodes_to_first, seconds
seed.library.Library.load(path)/save(path)    # aos/seedlib/blocks.json；Block = {name, body(帶 $h0..$h1 槽), sig, src_tasks, saving, uses}
```

- `near` 給 G4 演化當種子（train 像素對率最高的前幾支，B 算分數也行）。
- 觀察等價去重以 train 輸入上的輸出 hash 為鍵；節點數＝枚舉器建出的候選程式數（不是秒）。
- 測試：`tests/seed/`；兩次同設定 `enumerate` 結果完全相同（確定性）。
