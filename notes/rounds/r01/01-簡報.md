**讀法**：規劃者**只讀本檔**就要能定第一輪範圍、方法、驗收數字；不需要、也不應該去廣讀 repo。本檔的事實都已核過（數字來自 `docs/inventory/training-features.csv` 與現有報告）。

## 1. 目標與使用者前提（原話整理）

- 目標：用 aos 體系（符號邏輯）解 ARC-AGI-1。每題給 2～10 組 input→output 範例（多數 3 組），要對 test input 產生**完全正確**的輸出網格（top-1 exact match，整題所有 test 都對才算）。
- 使用者原話：「就是拿我們這套aos體系去嘗試解arcagi。」「因爲是純粹邏輯判斷……他那邊可以盡量多寫程式，包括用暴力解大量吃cpu，或是寫cuda程式(我有裝)。神經網路盡量不要，他那個有不確定性。」「他那邊其實可以直接開始試試看了。跟我們這邊的輪次一樣。」
- 長期路線（使用者 11-07 晚）：純 LLM 是錯的路；ARC-AGI-1 是「智能種子」。**LLM 只當出入口與輔助**（找規則、寫程式、蒸餾），最終解題靠確定的程式；把 LLM 解題的過程沉澱成可重用的規則／程式，種子長大後能自我吸收、遞迴改進。
- 方向問題不停線：隊長代定、記 `代定清單.md`，回報時給使用者翻案。
- 第一輪範圍小（aos 原話建議「挑一類容易寫成規則的題」）。

## 2. 不可違反的約束

| 約束 | 說明 |
|---|---|
| 成績以 **evaluation 400 題**為準 | training 400 題有 re-arc 現成 DSL 解答（洩漏風險），training 只當開發集 |
| 不用神經網路 | 規則、搜尋、暴力枚舉、CUDA 都可以 |
| 不新增 Python 依賴 | 專案目前**零依賴**（純 stdlib，連 numpy 都沒裝）；要依賴得問使用者 → 第一輪純 Python，或另開 C++/CUDA 子資料夾走外部程式介面 |
| 機器安全 | CPU 批次 `nice -n 19`、≤12 worker、單批 ≤16GB、顯存 ≤12GB、swap 只有 512MB；**同時只跑一條全量評測** |
| 額度緊 | 帳號本週已用 >81%：第一輪要能在少量 agent 工時內做完，不重複跑全量 |
| 程式碼規矩 | 模組放 `src/arcagi/<領域>/`，單檔 >300 行要拆；pytest 測試；commit 附 evaluation 改前／改後題數 |

## 3. 現有量具（已完成，直接用）

- 求解器介面：Python plugin `module:function`，收 `SolverTask`（`train` 範例、`test` 輸入、`Grid`＝tuple of tuples，值 0–9），回傳預測清單或 `SolverResult(predictions, trace)`。也可外部程式（任何語言，JSON 檔進檔出，`arcagi eval --external "cmd {input} {output} {trace}"`）。
- 評測：`arcagi eval --split training|evaluation --solver X --timeout S --output R.json --traces T.jsonl`。**逐題序列執行**（每題可獨立程序＋逾時），沒有內建平行；400 題 × 每題 3 秒 ≈ 20 分鐘。
- 嘗試軌跡 `arcagi-trace/1`：每題記 attempts（description、program、train_results、selected、耗時、reasoning、data），`TraceRecorder`＋`check_on_train` 是現成 helper。`--traces` 輸出把軌跡和對錯接在一起，是日後蒸餾的原料。
- 比較：`arcagi compare base=A.json new=B.json --labels training-features.csv --label-column category`：逐題對錯、新增解出／退步、按題型分組。
- 基線：identity 0/400（兩個 split）；template（只試整張網格 5 種對稱）training 6/400、evaluation 0/400。
