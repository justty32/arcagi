第一輪代定清單：使用者外出時隊長（opus）代定的方向問題。每條：決定了什麼、為什麼、怎麼翻案。

| # | 決定 | 理由 | 翻案方式 |
|---|---|---|---|
| D1 | 第一輪範圍＝整張網格變換 DSL＋一條「抽物件→選→裁」路徑（fable 案 A＋） | 小、快、可長大；先驗證架構再打物件大宗 | 指定別的題型或直接上物件層，下一輪改範圍 |
| D2 | **符號規則表示＝JSON 列表 S 式**：`[["split_overlay","v","xor"],["colormap",[[10,3]]]]`，每步＝原語名＋參數 | LLM 能寫、C++／CUDA 能重寫執行器、能原樣存進軌跡供蒸餾；比 Python 函式組合可序列化 | 改成樹狀 S 式（允許分支、多輸入）或別的格式：只動 `dsl/program.py` 與搜尋 |
| D3 | 搜尋＝逐層 BFS（深度 ≤3）＋觀察等價去重（所有 train 中間網格相同就剪）；**參數從範例推**（倍數由尺寸比、顏色由換色表） | progsynth_cpp 的 OE 實證有效；推參避免盲枚爆炸；不先分類（分類是粗標，誤分會漏解） | 改成按題型分派或 beam／best-first：只動 `solvers/search.py` |
| D4 | 多解選**最短程式**（步數＋參數 0.1＋表格每列 0.05，近似 MDL），同分取先找到 | 確定、可重現；CompressARC 支持 MDL | 改投票或保留第二候選（ARC 正式規則允許 2 次嘗試，本量具是 top-1） |
| D5 | 加「終端學習器」：換色表、鄰域規則表（中心＋4／8 鄰居→顏色），不佔深度、每個節點都試；test 出現沒見過的鍵就放棄 | 一次覆蓋 colormap／split_overlay 上色／部分 fill；表格是確定的查表規則，也是蒸餾候選 | 拿掉或限制只在深度 0 用：`search.py` 的 `evaluate` |
| D6 | 中間網格允許**標記色 10**，最後必須被換色表映回 0–9，否則程式無效 | 「切半疊合」「填封閉區」不用先猜顏色，深度省一層 | 改成原語帶顏色參數（多一層枚舉） |
| D7 | 鄰域規則不設最低支持數（試過 ≥2：training 57→54） | 評分是 top-1，答錯不扣分；過擬合只在沒有更短解時才被選到 | 若改用 2 次嘗試或要「寧缺勿錯」，把 `learners.MIN_SUPPORT` 改 2 |
| D8 | 純 Python、零依賴，不上 C++／CUDA | 全量 evaluation 只要 81 秒、無一題逾預算：瓶頸是原語覆蓋，不是算力 | 原語變多、深度 ≥4 開始逾時再上 C++（同一 JSON 程式格式，經 `--external` 接） |
| D9 | 程式放正式模組 `src/arcagi/dsl/`＋`src/arcagi/solvers/search.py`，不另開試驗場 | 直接吃現有量具（eval、traces、compare）與 CI；aos 指令暫無需要 | 要用 aos 的資料夾＝程式形式時，在 arcagi 下開 `playground/` 包裝同一 DSL |
| D10 | **怎麼從 LLM 蒸餾（方向，本輪未做）**：LLM 看題寫 D2 格式程式 → 執行器驗 train → 過的進軌跡 → 從所有過 train 程式抽高頻片段註冊成巨集原語（Stitch 式 library learning）→ 原語做使用率記帳、長期 0 用就退休（node-pool 想法） | LLM 只當「提案者」，最終解題仍是確定的程式；蒸餾產物＝新原語，可累積、可壓縮 | 改成「LLM 直接寫 Python 原語」或「蒸餾成題型分派規則」 |
| D11 | 軌跡記：全部過 train 的程式（≤30）、像素正確率最高的近失敗（≤20）、題目特徵、各深度節點數 | 正例供 library learning、負例供學排序；全記失敗會爆量 | 改 `search.py` 的 `MAX_SOLUTIONS`／`MAX_NEAR` |
| D12 | 全量評測本輪只跑一次（training、evaluation 各一），開發中只跑 training | 遵守「evaluation 為準、不拿 evaluation 調參」；額度與機器負擔 | — |
