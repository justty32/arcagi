## 2. 做了什麼（程式方法）

- `src/arcagi/dsl/`：18 個網格原語（翻轉旋轉、縮放、鋪磚、鏡像鋪、裁內容框、切半疊合 AND/OR/XOR/NOR、抽物件挑一個裁出、填封閉區、自我鋪磚、補對稱、重力）＋2 個終端學習器（換色表、鄰域規則表）；程式是 JSON 列表。
- `src/arcagi/solvers/search.py`：逐層枚舉到 3 步、觀察等價去重、參數從範例推、最短程式勝出；每題軌跡記全部過 train 的程式＋近失敗，`--traces` 存成 JSONL 供蒸餾。
- 測試：`tests/dsl/test_dsl.py`、`tests/solvers/test_search.py`（全套 238 綠）。

## 3. 得失

**得**
- 架構驗證：新原語＝registry 加一筆，搜尋不用改；第二批原語（自我鋪磚、補對稱、重力）是另開一檔加進來的，沒動搜尋。
- 「標記色 10＋終端換色表」很划算：切半疊合類 10 題、填封閉區類全靠它，不用枚舉顏色。
- 搜尋遠沒用完預算（每題最長約 1 秒）→ **瓶頸是原語覆蓋，不是算力**；C++／CUDA 暫時用不到。

**失**
- 過擬合：evaluation 有 10 題「過了 train 但答錯」，多是「裁物件＋放大＋鄰域規則表」在很小的輸出上背答案。加支持數門檻會連帶少解 3 題，已回退（代定 D7）。
- 物件層幾乎沒碰：fill／recolor／same_mixed（training 合計 215 題）只解 7 題，是下一輪最大的池子。
- 蒸餾只備了原料（軌跡），沒有實際抽片段或接 LLM。

## 4. 代定（摘要，全文 [代定清單](代定清單.md)）

規則表示＝JSON 列表 S 式（D2）；搜尋＝BFS＋觀察等價＋從範例推參（D3）；多解取最短（D4）；終端學習器與標記色（D5、D6）；純 Python 不上 C++（D8）；**蒸餾方向**＝LLM 寫 JSON 程式→驗 train→抽高頻片段成新原語→使用率記帳退休（D10）。

## 5. 下一輪方向（建議）

1. **物件層**：逐物件抽取→屬性（大小、顏色、形狀、位置）→逐物件變換或上色→畫回原圖；目標打 fill／recolor／same_mixed。
2. **格線切塊**：有分隔線的網格切成小格，對小格做摘要或選擇（evaluation 常見）。
3. **第一次 library learning**：從 training 57 題的過 train 程式抽共同片段，看能不能壓出巨集原語、加深搜尋。
4. **過擬合對策**：多解投票或在量具加 top-2（ARC 正式規則允許 2 次嘗試）分開記分。
5. LLM 入口（若額度允許）：讓 LLM 看沒解出的題寫 JSON 程式，量「LLM 提案→程式驗證」的產率。
- 驗收建議：evaluation ≥35/400（新增 ≥14 題）、training ≥90/400；仍保持每題 ≤3 秒。
