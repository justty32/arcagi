## 6. 整題模式 `--mode seed`（照 S1 草案）

```
native/bin/arcbatch --mode seed (--tasks LIST | --taskset data/r07/taskset.json [--split learn,holdout])
    [--data-dir DIR] --configs CONFIGS.jsonl [--threads N] [--out OUT.jsonl]
```

- 設定檔每行一個：`{"name", "lib": "<blocks.json>", "budget": 100000, "decomp": false, "lam_depth": 2, "exclude": ["transpose"], "order": {"名": 權重}}`。
  - `decomp` 在 C++ 只接受 `false`，也就是 Python `seed.enum.solve(train, lib, budget, order, decompose=False)`。要分解就由 Python 驅動 §7；`true` 或拆法名單一律回錯，訊息寫「use seed-sub」。
  - `lam_depth`：lambda body 深度上限（grow 的旋鈕，等於改 `lam.LAM_DEPTH`）。`exclude`＝`prims.without(*names)`。`order`：運算子先依權重由大到小排，同分照 PRIMS 表的順序（`lam.build_ops`）。
- 輸出每行一筆（題 × 設定）：`{task_id, config, program, train_ok, test_ok, nodes, nodes_to_first, seconds, near, eval_steps}`。`near` 是 `[[program, score], …]`，跟 Python `Result.near` 同序同值；`eval_steps` 是近似值，不比對。最後一行是 summary。
- 過渡期也可以照原規劃的寫法 `arcbatch --lang seed --lib <blocks.json> --tasks <json> --budget N --out <jsonl>`，每題回最多 3 支 `{task, program, nodes, train_ok}`；兩種寫法擇一，S1 已經提了上面這個介面，就以上面為準。

## 7. 子目標批次 `--mode seed-sub`（新增，Python 拆、C++ 枚舉）

一個子目標就是一次 `seed.enum.Enumerator(...)` 加上一次 `search`（必要時再加一次 `cond_witness`）。輸入是 JSONL，每行一個子目標：

```json
{"id": "496994bd/3", "lib": "<blocks.json>", "budget": 6930,
 "examples": [[<input value>, <output value>], ...],
 "in_type": "list[list[int]]", "out_type": "list[list[int]]",
 "extra": [{"leaf": "$u", "type": "list[list[int]]", "vals": [<value per example>, ...]}],
 "sub": true, "consts": [-1, 0, 1, 2, 3],
 "lam_depth": 2, "lam_body_max": 4, "order": {}, "exclude": [],
 "cond_limit": null}
```

| 欄位 | 對應 Python | 說明 |
|---|---|---|
| `examples` | `train` | 去重後的 (輸入, 輸出) 例對；值可以是 int、bool、list。子目標的「輸入」可能是一列、一個元素，或切出來的半段 |
| `in_type`／`out_type` | `in_type`／`out_type` | `$in` 的型別與目標型別。目標判定：同型別、而且在所有例對上的值都相等 |
| `extra` | `extra` | 額外的大小 1 葉子（`$i` 位置、`$u`／`$v` 半段、`$v` 配對元素），值逐例給定；在 `$in`、整數字面值、無洞積木之後依序加入 bank。**lambda body 裡不可以出現** |
| `sub` | `sub` | `true`：lambda body 裡看不到 `$in`、不留 near、積木庫已由呼叫方換成 `sub_library`；`false`：跟整題一樣（`$in` 可以進 lambda、留 near） |
| `consts` | `consts` | 整數葉子，照給的順序 |
| `lam_depth`／`lam_body_max` | `lam_depth`／`lam_body_max` | lambda body 深度與大小上限；盲枚舉是 2／4，`nest` 開時子目標是 3／6 |
| `cond_limit` | `cond_witness(en, limit)` | 非 null 時，如果枚舉沒找到，就用 bank 跑條件見證，最多建 `cond_limit` 個 (c, t, e) 組合（演算法見 `seed/cond.py`：else 候選依命中數多、出現早排序，取前 12 個；t 要涵蓋 else 沒中的例對；c 是 bank 裡的布林項，要在需要 t 的例對上為真、在 t 錯的例對上為假） |

輸出每行一筆：`{"id", "program": <JSON 或 null>, "nodes", "nodes_to_first", "near": [[program, score], …], "cond": {"program": <或 null>, "used": n}, "eval_steps"}`。`nodes` 必須跟 Python 的 `en.nodes` 一模一樣：每建一個候選算 1 個節點，包括求值失敗的和被去重掉的；達到 `budget` 就停。

- 拆法的預算切法、子目標的先後、組回程式、驗證整支程式，全部留在 Python（`decomp._Solver`）。每個子目標（找到也好、沒找到也好）的 `nodes` 加上 `cond.used` 都要全額記進該題預算（D-r8-8，`tests/seed/test_seed_splits.py::test_all_subsearch_nodes_are_charged` 有驗）。
- **批次粒度**：同一題的子目標有先後依賴（後面子目標的預算要看前面花了多少），所以一批是「很多題各自的下一個子目標」，不是同一題的所有子目標。Python 端怎麼排程是 B 線／隊長的事，C++ 只要能一次吃一批 JSONL、平行跑完就好。
- 一致性測試：Python 端把 `_Solver._direct` 的每次呼叫錄成上面的 JSONL（含結果），C++ 重跑後逐行比對 `program`／`nodes`／`nodes_to_first`／`near`／`cond`。這支錄製工具 A 線還沒做，S1 真的接上時再補。
