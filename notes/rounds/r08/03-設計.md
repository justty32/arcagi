## 1. 開工前預測（隊長實跑，scratchpad `r08/probe_pool.py`）

r07 最終 seed（efdee5d）、分解開、空庫、12 workers，對 training 扣 L16／H8 的 **376 題**（不限尺寸）：

| 每題預算 | 牆鐘 | 過 train | train＋test 都對 |
|---|---|---|---|
| 100k | 14 秒 | 19 | 17 |
| 1M | 206 秒 | 28 | 21 |

→ 練習池在 Python 端就便宜，**不必等 S1**；過 train 但 test 錯的比例隨預算上升（2→7），「test 也對」的濾網是必要的。

## 2. 對規劃的調整（代定，見代定清單）

- **D-r8-1 練習池取全部 376 題**，不加 ≤15×15 上限：實測 100k 只要 14 秒，大格題不是算力瓶頸。尺寸偏置因此消失（L16／H8 仍維持 r07 題組不變，好跟 32 直接比）。
- **D-r8-2 P 預算**：25k 起、每 pass ×2、封頂 **400k**（照規劃）；預估 pass 4 起每 pass 約 90 秒。L16／H8 固定 100k。
- **D-r8-3 CRN 的隨機源**：分解＋G1 全確定，5 個 seed 只換 G4 隨機源的話，G4 關時 5 條一模一樣、配對 SE＝0，判準會退化。所以 seed 也決定**練習池的抽樣**：每個 seed 取 P 的固定 80% 子集（`sha1(task_id+str(seed))` 排序取前 80%）。這樣量的是「旋鈕對換一批練習題是否穩健」，前後同 seed 用同一子集與同一 G4 源（配對）。
- **D-r8-4 C 線不開**：寄 S1 信、收輪 gated 由隊長自己做（量小）；同時只開 A、B 兩條 opus 線，第三格留給雜活或接手。
- **D-r8-5 拆法預設**：r07 已有的拆法全在 `DEFAULT_SPLITS`；r08 新增的 `halves`、`nest` 預設**關**，要經 B 線 CRN 判準接受才進主樹（「加拆法」＝ meta 動作，記 `kind=r08-agent`）。主樹名 `pool`＝分解（DEFAULT）＋G1＋練習池；`pool-g4` 再開 G4。

## 3. A↔B 介面（寫死；B 前段用舊簽名跑，A 合入後切換）

```python
# src/arcagi/seed/  (A 寫)
seed.decomp.SPLITS: tuple[str, ...]          # 全部拆法名（r07 的 map, zip_pos, if, take, conj_transpose, conj_reverse, append ＋ r08 halves, nest）
seed.decomp.DEFAULT_SPLITS: frozenset[str]   # r07 那 7 個
seed.enum.solve(train, lib, budget, order=None, decompose: bool | frozenset[str] = True,
                sub_lam_depth: int | None = None) -> Result
    # decompose=True ≡ DEFAULT_SPLITS；False ≡ 空集合；frozenset 只開列名者
    # sub_lam_depth：拆法子搜尋內 lambda 體深上限（None＝同盲枚舉 LAM_DEPTH）；`nest` 拆法用它開 3
seed.enumerate(..., decompose=..., sub_lam_depth=...)   # 同步轉傳
```

- 舊呼叫（`decompose=True/False`）行為與 r07 **逐位相同**：A 線要附一個測試，r07 L16 在 `DEFAULT_SPLITS` 下 pass 0 解的 4 題與節點數不變。
- B 線的 `grow/backend.solve_with` 改傳 `decompose` 集合與 `sub_lam_depth`；旋鈕 `decomp_set`（字串集合）與 `sub_lam_depth`（2／3）加進 `grow/knobs.py`。
