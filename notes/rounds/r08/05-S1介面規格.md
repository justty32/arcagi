## 0. 分工（D-r8-13）

- **Python 管拆法**：`seed.decomp`（map、zip_pos、if、take、conj_*、append，以及 r08 的 halves、nest）負責拆出子目標、分預算、把子解組回整支程式。
- **C++ 只做枚舉**：給一個子目標（例對清單＋型別＋葉子＋限制），跑 `seed.enum.Enumerator` 同一套由小到大、型別導向、觀察等價去重的枚舉，回傳找到的程式與節點數。**C++ 不重寫拆法。**
- 有兩種呼叫：整題（`--mode seed`，等於 `decompose=False` 的純枚舉）和子目標批次（`--mode seed-sub`，§7）。另有 `--mode seed-run`（§8）做差分測試。
- 真值以 Python 為準。如果規格跟 Python 對不上，以 Python 為準，並回報這份規格哪裡寫錯。C++ 吐出的每支程式，Python 都會用 `seed.interp.run` 重驗；不一致就作廢，`curve.csv` 記一筆 `native_mismatch`。

## 1. 值與型別

- 值只有三種：整數、布林、list（可以巢狀、可以 ragged、可以空）。JSON 裡整數就是整數，布林是 `true`／`false`，list 是陣列。任務網格就是 `list[list[int]]`。
- 型別字串（`types.show`／`types.parse`）：`int`、`bool`、`list[T]`、函式 `(A, B) -> R`（單參數也可以寫 `A -> R`），型別變數就是任意識別字（`a`、`b`、`c`）。合一（unify）是標準 Hindley–Milner 風格，有 occurs check，不支援 tuple 型別。
- 任務的輸入和輸出型別都是 `INPUT = list[list[int]]`。

## 2. 程式 JSON（`interp.to_json`／`from_json`）

| 形式 | JSON | 意義 |
|---|---|---|
| 整數字面值 | `3`、`-1` | 常數葉子 |
| 輸入 | `["$in"]` | 該題（或子目標）的輸入值；任何深度都看得到 |
| lambda 參數 | `["$0"]`、`["$1"]` | **最內層** lambda 的第 0／1 個參數 |
| lambda | `["lam", n, body]` | n ∈ {1, 2}；n 是 JSON 整數 |
| 原語呼叫 | `["add", a, b]` | 名稱必須在 PRIMS 裡，參數數量要對 |
| 積木 | `["blk", name, a0, a1]` | 積木庫的積木，參數依序填進洞 `$h0`、`$h1` |
| 子目標葉子 | `["$u"]`、`["$v"]`、`["$i"]` | 只會出現在 §7 的子目標裡（值由呼叫方給）；組回整支程式後就不會再出現 |

- **lambda 環境不疊加**：進入內層 lambda 時，參數環境整個換成內層的參數，所以內層看不到外層的 `$0`、`$1`（`$in` 還是看得到）。例如 `["zipwith", ["lam", 2, ["zipwith", ["lam", 2, ["max", ["$0"], ["$1"]]], ["$0"], ["$1"]]], A, B]`：外層 lambda 的 `$0`、`$1` 是兩列，內層的 `$0`、`$1` 是兩個元素。
- **大小**（`interp.size`）：葉子算 1；原語呼叫算 1 加上各參數的大小；lambda 本身不算，只算 body；`blk` 算 1 加上各參數的大小（不展開）。

## 3. 積木庫 `blocks.json`（`seed.library`）

- 檔案是 JSON list，每個元素 `{name, body, sig, src_tasks, saving, uses}`（grow 另外加了 `born`、`holes`、`idle`，讀的時候忽略）。
- `body` 是程式 JSON，可以含洞 `["$h0"]`、`["$h1"]`。`sig`：有 k>0 個洞時，是 k 個參數的函式型別（參數就是洞的型別，回傳是積木的型別）；沒有洞時就是積木本身的型別，可能是函式型別（這時積木當 lambda 用）。
- **展開是語法替換**：先把 `blk` 的參數程式代進洞，再求值。所以洞如果在 lambda 裡，填進去的程式可以引用那個 lambda 的參數。r07 實例 `d10ecb37`：`["map", ["lam", 1, ["blk", "g1_0fe6fca1dc", ["$0"]]], …]`。
- 枚舉只用 body 裡沒有自由 `$0`／`$1` 的積木（在積木自己的 lambda 之外）。有洞的積木當運算子（ops），沒洞而且不是函式型別的當葉子，沒洞而且是函式型別、參數型別剛好相符的，當大小 1 的 lambda。子目標（sub）另外排除兩種積木：body 用到 `$in` 的，和有洞在 lambda 裡的（`decomp.sub_library`）。

## 4. 求值語意（`seed.interp`）

- 每次原語呼叫扣 1 步。上限 `MAX_STEPS = 200000`，超過就丟 `EvalError`。字面值、`$in`、`$k`、lambda 建構都不扣步。
- 所有失敗都變成 `EvalError`（JSON 輸出寫 `"ERR"`），包括：空 list 取 `head`、`nth` 越界或負索引、`mod` 除以 0、型別不合（例如對整數取 `len`）、超出資源上限。
- 資源上限：list 長度超過 `MAX_LEN = 1024` 時 `cons`／`append`／`concat`／`range`／`repeat` 會丟錯；`add`／`sub`／`mul` 的結果超出 ±`MAX_INT = 10**9` 時丟錯（`neg`、`mod` 不檢查）。
- 整數語意照 Python：`mod` 是 floor mod（`-7 mod 3 = 2`、`7 mod -3 = -2`）；`sort` 的順序是 Python 的全序：整數照大小、list 照字典序、布林 False < True；`eq` 是深層相等。
- 32 個原語的型別簽名在 golden 檔的 `sigs` 欄位。每個原語的邊界語意（ragged 的 `transpose` 跟 Haskell `Data.List.transpose` 一樣：跳過太短的列；`take`／`drop`／`range`／`repeat` 的負數當 0；`fold f z xs` 的 `$0` 是累積值、`$1` 是元素）都以 golden 為準。
- **golden**：`tests/seed/golden_prims.json`，每個原語 20～30 組，共 747 組，含 ragged、負數、空 list、溢位、ERR。每組是 `{program, input, output[, args]}`：`program` 是只用到這一個原語的整支程式（整數參數寫成字面值；list／bool 參數從 `$in` 取，只有一個就是 `["$in"]` 本身，多個就用 `["nth", ["$in"], j]` 取；函式參數寫成 lambda），`input` 是 `$in` 的值，`output` 是值或 `"ERR"`；一階原語另外附 `args`（參數值）。C++ 必須全部通過。重產指令：`uv run python tests/seed/make_golden_prims.py`（`tests/seed/test_golden_prims.py` 會驗證檔案和 Python 一致）。

## 5. 整數字面值（`prims.task_consts`）

葉子整數＝{0, 1, −1} ∪ 例對（輸入與輸出）中出現的每個整數 ∪ 每個巢狀 list 的長度，排序後去重。整題模式由 train 的輸入和輸出算；子目標模式由呼叫方直接給 `consts`（Python 用整題的 consts，不是子目標的）。

## 6. 整題模式 `--mode seed`（照 S1 草案）

```
native/bin/arcbatch --mode seed (--tasks LIST | --taskset data/r07/taskset.json [--split learn,holdout])
    [--data-dir DIR] --configs CONFIGS.jsonl [--threads N] [--out OUT.jsonl]
```

- 設定檔每行一個：`{"name", "lib": "<blocks.json>", "budget": 100000, "decomp": false, "lam_depth": 2, "exclude": ["transpose"], "order": {"名": 權重}}`。
  - `decomp` 在 C++ 只接受 `false`，也就是 Python `seed.enum.solve(train, lib, budget, order, decompose=False)`。要分解就由 Python 驅動 §7；`true` 或拆法名單一律回錯，訊息寫「use seed-sub」。
  - `lam_depth`：lambda body 深度上限（grow 的旋鈕，等於改 `lam.LAM_DEPTH`）。`exclude`＝`prims.without(*names)`。`order`：運算子先依權重由大到小排，同分照 PRIMS 表的順序（`lam.build_ops`）。
- 輸出每行一筆（題 × 設定）：`{task_id, config, program, train_ok, test_ok, nodes, nodes_to_first, seconds, near, eval_steps}`。`near` 是 `[[program, score], …]`，跟 Python `Result.near` 同序同值；`eval_steps` 是近似值，不比對。最後一行是 summary。
- 過渡期也可以照原規劃的寫法 `arcbatch --lang seed --lib <blocks.json> --tasks <json> --budget N --out <jsonl>`，每題回最多 3 支 `{task, program, nodes, train_ok}`；兩種寫法擇一，S1 已經提了上面這個介面，就以上面為準。

## 7. 子目標批次 `--mode seed-sub`（新增，Python 拆、C++ 枚舉）

一個子目標就是一次 `seed.enum.Enumerator(...)` 加上一次 `search`（必要時再加一次 `cond_witness`）。輸入是 JSONL，每行一個子目標：

```json
{"id": "496994bd/3", "lib": "<blocks.json>", "budget": 6930,
 "examples": [[<input value>, <output value>], ...],
 "in_type": "list[list[int]]", "out_type": "list[list[int]]",
 "extra": [{"leaf": "$u", "type": "list[list[int]]", "vals": [<value per example>, ...]}],
 "sub": true, "consts": [-1, 0, 1, 2, 3],
 "lam_depth": 2, "lam_body_max": 4, "order": {}, "exclude": [],
 "cond_limit": null}
```

| 欄位 | 對應 Python | 說明 |
|---|---|---|
| `examples` | `train` | 去重後的 (輸入, 輸出) 例對；值可以是 int、bool、list。子目標的「輸入」可能是一列、一個元素，或切出來的半段 |
| `in_type`／`out_type` | `in_type`／`out_type` | `$in` 的型別與目標型別。目標判定：同型別、而且在所有例對上的值都相等 |
| `extra` | `extra` | 額外的大小 1 葉子（`$i` 位置、`$u`／`$v` 半段、`$v` 配對元素），值逐例給定；在 `$in`、整數字面值、無洞積木之後依序加入 bank。**lambda body 裡不可以出現** |
| `sub` | `sub` | `true`：lambda body 裡看不到 `$in`、不留 near、積木庫已由呼叫方換成 `sub_library`；`false`：跟整題一樣（`$in` 可以進 lambda、留 near） |
| `consts` | `consts` | 整數葉子，照給的順序 |
| `lam_depth`／`lam_body_max` | `lam_depth`／`lam_body_max` | lambda body 深度與大小上限；盲枚舉是 2／4，`nest` 開時子目標是 3／6 |
| `cond_limit` | `cond_witness(en, limit)` | 非 null 時，如果枚舉沒找到，就用 bank 跑條件見證，最多建 `cond_limit` 個 (c, t, e) 組合（演算法見 `seed/cond.py`：else 候選依命中數多、出現早排序，取前 12 個；t 要涵蓋 else 沒中的例對；c 是 bank 裡的布林項，要在需要 t 的例對上為真、在 t 錯的例對上為假） |

輸出每行一筆：`{"id", "program": <JSON 或 null>, "nodes", "nodes_to_first", "near": [[program, score], …], "cond": {"program": <或 null>, "used": n}, "eval_steps"}`。`nodes` 必須跟 Python 的 `en.nodes` 一模一樣：每建一個候選算 1 個節點，包括求值失敗的和被去重掉的；達到 `budget` 就停。

- 拆法的預算切法、子目標的先後、組回程式、驗證整支程式，全部留在 Python（`decomp._Solver`）。每個子目標（找到也好、沒找到也好）的 `nodes` 加上 `cond.used` 都要全額記進該題預算（D-r8-8，`tests/seed/test_seed_splits.py::test_all_subsearch_nodes_are_charged` 有驗）。
- **批次粒度**：同一題的子目標有先後依賴（後面子目標的預算要看前面花了多少），所以一批是「很多題各自的下一個子目標」，不是同一題的所有子目標。Python 端怎麼排程是 B 線／隊長的事，C++ 只要能一次吃一批 JSONL、平行跑完就好。
- 一致性測試：Python 端把 `_Solver._direct` 的每次呼叫錄成上面的 JSONL（含結果），C++ 重跑後逐行比對 `program`／`nodes`／`nodes_to_first`／`near`／`cond`。這支錄製工具 A 線還沒做，S1 真的接上時再補。
