## 1. 結論

照 fable：公式型（A 線）、抽取型（B 線）兩個產生器＋背景／投票／帳（C 線），不碰 LLM。隊長改四處（記代定）：

- **路徑沿用現有佈局**：不新開 `src/arcagi/features/`、`objects/`、`search/` 套件，改放 `src/arcagi/dsl/` 與 `src/arcagi/solvers/`（D-r3-1）。
- **背景用「題目層級」**：`Primitive.apply(grid, …)` 一次只看一張網格，看不到同題別的 pair → 搜尋開始時算出題目背景（所有 train 輸入＋輸出的共同眾數，平手取邊框色）設進 `dsl/background.py` 的 context，物件抽取優先用它；沒設時行為同 r02（D-r3-2）。
- **生成原語各線自己管**：公式參數的原語（`canvas`、`tile_n`…）歸 A、抽取參數的原語（`crop_extract`、`fill_extract`…）歸 B，避免兩線寫同一檔；registry 接線由隊長做（D-r3-3）。
- **尺寸剪枝改成「尺寸提示」**：中間層尺寸「不可達」難定義，改成 A 提供 `predict_shapes(train_pairs, test_inputs)`，C 的投票把測試輸出尺寸不符提示的解降級——同時是防背答案（D-r3-4）。
- 退休「真的執行」＝把 `_metainfo.json` 的 status 改 `retired`（registry 已會略過），不搬資料夾（D-r3-5）。

## 2. 分線（同時 3 條，各寫各的檔）

| 線 | 可寫 | 公開介面（隊長整合用） |
|---|---|---|
| A 公式 | `dsl/features.py`、`dsl/formula.py`、`dsl/formula_prims.py`、`blocks/gen_formula.py`、`aos/blocks/formula_*`、`aos/blocks/_gen/formula/`、`tests/dsl/test_formula.py`、`tests/blocks/test_gen_formula.py` | `features.compute(grid)->dict[str,int]`；`Formula`（JSON `{"kind":"formula","in":"features","out":"int","body":[op,…]}`）、`formula.fit(xs: list[dict], ys: list[int], library) -> body\|None`、`formula.evaluate(body, feats)->int`；`FORMULA_PRIMS: dict[str, Primitive]`；`install(rules: dict[名字, _rule.json])`（registry 已預接：模組存在就 import、呼叫 install、併入 ALL）；`predict_shapes(train_pairs, test_inputs) -> list[(h,w)]\|None` |
| B 抽取 | `dsl/extract.py`、`dsl/extract_prims.py`、`blocks/gen_extract.py`、`aos/blocks/extract_*`、`aos/blocks/_gen/extract/`、`tests/dsl/test_extract.py`、`tests/blocks/test_gen_extract.py` | 抽取 JSON `{"kind":"extract","in":"grid","out":"json","body":[…]}`、`extract.run(body, grid)`；`EXTRACT_PRIMS: dict[str, Primitive]`；`install(rules)`（同 A） |
| C 背景＋投票＋帳 | `dsl/background.py`、`dsl/objects*.py`、`solvers/search.py`、`solvers/vote.py`、`blocks/pool.py`、`aos/pool/`、`tests/dsl/test_background.py`、`tests/solvers/test_vote.py`、`tests/solvers/test_search.py`、`tests/blocks/test_blocks_accounts.py` | `background.set_task_background(c\|None)`、`background.task_background(grids)`；搜尋 `solve()` 用投票選 top-1／top-2，可吃 `shape_hint`；pool：essential、巨集分紅下傳、產生器成本、真退休、產生器預算建議 |
| 隊長 | `dsl/registry.py`、`dsl/program.py`、`blocks/catalog.py`（已加 `Catalog.rules(kind)`）、notes、reports、ledger | 整合、跑全量、記帳 epoch 3 |

- **A／B 的「產生器→積木→搜尋」迴路**（同 r02 謂詞）：產生器在 training 枚舉式子、評分（題數，支持數≥2 種特徵值／跨 pair 一致）、0 分不落地、同支持集留最短其餘 covered；落地 `aos/blocks/<kind>_<hash>/{_metainfo.json,_rule.json,_entry}`（metainfo 記 `generator`、score、support_tasks、covered_by）；產生器節點 `aos/blocks/_gen/<kind>/{_metainfo.json,_entry}`（`_entry` 跑產生器，`aos-exec --ws aos aos/blocks/_gen/formula --dry-run` 可叫）。搜尋時原語的 `candidates` **先試 live 積木庫裡的式子**，庫沒有才用小範圍直接擬合（上限寫在模組常數）。
- 生成原語範例：A——`canvas(hf, wf, color)` 新畫布（尺寸由公式算）、`tile_n(nf_y, nf_x)` 重複次數由公式算、`resize_crop(hf, wf)` 從左上角裁／補到公式尺寸；B——`crop_extract(body)` 裁出抽取的框、`fill_extract(body)` 整格塗抽取的顏色、`paint_count(body, color)` 畫出抽取計數的條／方塊、`keep_extract(body)` 只留抽取到的物件。各線可增刪，但每個原語 `candidates` 要便宜（不適用立刻回 `[]`）。
- C 的物件背景要 A、B 也受益：C 在 30 分鐘內先交 `dsl/background.py`＋`objects_props.extract` 改用它（向後相容），A、B 直接用 `objects_props.extract`。

## 3. 投票（C）

到第一個有解的深度後**收完該深度**（每題解數上限 200，時間預算不變 5 秒）；按測試輸出分組，組票數＝Σ權重（含學習器 `colormap`／`object_colormap`／`local_rule` 的解權重 0.5）；top-1＝最便宜的解（同成本取票多），**若有尺寸提示且 top-1 尺寸不符而有符合的解，換成符合的最便宜解**；top-2＝票最多的不同輸出（寫 `metadata.second`，`scripts/score_top2.py` 照算）。`local_rule` 照舊排後。

## 4. 帳（C）

`aos/pool/config.json` 加 `essential`（隊長手列：flip_lr、flip_ud、rot90、rot180、rot270、transpose、anti_transpose、crop_bbox，加全部物件選擇器原語）→ 永不進 suggest_retire；巨集分紅的 50% 按 `program.json` 成分下傳；產生器節點的花費＝產生耗秒×費率（metainfo `gen_seconds`）；真退休：只限 metainfo 有 `generator` 的積木、連 3 epoch 0 收入且 status=covered → status 改 retired、寫 ledger；epoch 檔加 `generator_budget`（按產生器淨收入比例、每台底線 20%，本輪只記不用）。

## 5. 驗收（fable 數字，照抄）

- evaluation ≥36（目標 40）、已解 28 退步 0；「尺寸隨輸入」54 題 ≥8；同大小 ≥11。training ≥95（目標 105）；過 train 答錯 ≤12。每題 ≤5 秒（eval `--timeout 15`）、全量 evaluation ≤400 秒。
- pytest 全綠：特徵、公式擬合、抽取、背景色、投票、帳。
- aos：`aos-exec` 可單叫兩個產生器；epoch 3 有產生器成本／收入、essential、≥1 個 pred_* 真退休（若條件成立）、formula_*／extract_* 各 ≥5 live。

## 6. 子線限制（寫進任務書）

不 commit／push（隊長收）；不動別線與隊長的檔；不新增依賴；不跑 evaluation；training 子集 ≤100 題、`systemd-run --user --scope -q -p MemoryMax=16G nice -n 19`；產生器全量掃 training 允許（只讀題目、不跑搜尋）；不寫 aos repo；單檔 ≤300 行；回報只要：改了哪些檔、pytest 結果、training 子集增量（指令＋數字）、落地積木數。
