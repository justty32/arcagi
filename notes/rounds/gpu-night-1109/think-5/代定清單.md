# think-5 代定清單（隊長代定，等使用者核）

← [01](01-簡報.md)｜[02 fable](02-規劃-fable.md)｜[02b Argon](02b-Argon審.md)｜上輪 [think-3 E1–E19](../think-3/代定清單.md)

**一句結論**：跨題合批與多層融合**現在都不做**。合批最多 1.35×（把一階原語補齊後 1.6×），而且用「超額執行緒＋阻塞式等待」不寫排程器就能拿到差不多的藏延遲效果。融合非得把 lambda 一起搬上 GPU 才不破語意，上限 5.7×，但要一到三個月，還受 E1／E5 約束。先量兩件事：乾淨 GPU 下的延遲，和每層候選數的分佈。

| 編號 | 題 | 預設 | 理由 | 翻案處 | 衝突 |
|---|---|---|---|---|---|
| G1 | 主線押哪 | **A 系**（不改架構：有預算上限的預發＋閾值調整）；B 合批、C 融合都不開工 | 合批封頂 1.35×／1.6×，同 A；融合需整列舉器＋L1 | 閘 0 量出乾淨 λ>5 ms **且** G2 分佈顯示大層佔 W_g ≥80% → 重議 B | — |

## 要使用者裁

1. 排一段 10–15 分鐘的**乾淨 GPU 窗口**（停所有夜跑），跑閘 0 的 λ 微基準和 G7 對照。
2. 開不開 **MPS**（G14，系統設定）。
3. **E1／E5** 要不要為融合 C 鬆綁（G12）；不鬆綁就是 C 永久擱置。
4. 准不准開 **03**，第一項是 G2 的加 log 量測（屬施工）。
5. CPU 熱點優化（G15）要不要另開一線。
