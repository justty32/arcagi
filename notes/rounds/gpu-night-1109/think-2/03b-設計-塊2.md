## 1. 先核過的事實（隊長查過原始碼，sol 不用再猜）

- `epoch.run_tree(root, "hammer", epochs=E, backend="native", threads=T, holdout=True)` 跑 epoch `0..E`（共 E+1 個）；`ops.jsonl` 已存在就不 init；從 `ledger.jsonl` 裡 `kind=epoch` 的最大 epoch+1 續跑，所以副本的 ledger 必須是空的。
- 預算：每題 `bud["L"]`（L16、H8、H24），P 題用 `pl.budget(P0…)`。`frozen.json.budgets.epochs` 不被 `run_tree` 讀（epoch 數由參數給），但仍一起覆寫保持一致。
- 洩漏點：`epoch.py:252` `gate_ids=set(ids["L16"]) | set(ids["P"])`；`epoch.py:335` shadow 的 `lp` 也含 P；`ids["P"]` 來自 `truth/train/taskset.json` 的 `P`。**把副本的 `P` 設 `[]` 就同時斷掉這兩處**（D17），不改原始碼。
- 活樹 comb 有 `payload.src_tasks`；21 列裡 12 列 comb 的 `src_tasks` 或 `evidence.new_solves` 碰 P（守門一對活樹必 FAIL，Argon 5.1 的「讀不到欄位」不成立）。`evidence` 在塊 1 被剝到 `state.json`，所以守門一讀 `tree_root/ops.jsonl`（含狀態）或 `tree.json`＋`state.json`。
- 每 epoch 的 `epochs/<n>/solutions.jsonl` 每題一列：`task_id, set, test_ok, train_ok, nodes, nodes_to_first`；`curve.csv` 一列。`scripts/think1_meter.py` 的 `summarize(root)` 算 `auc_L`（epoch≥1 的 `solved_L` 和）、`auc_speed_L`、`cost`、`eff`，用 importlib 從路徑載入，不改它。
- 活樹 9 epoch（L=100k）共約 5 分鐘：epoch 0～3 各 ~1 s，之後 ~75 s（`decomp_halves` live 走 python 後端）。
- 守門二目前命中（`src/`、`scripts/` 的 `*.py`）：`pixel_acc` 6 處；擴充樣式後另有 `near_best`／`near_score`／`near_miss`／`_gradients` 約 15 處（`hammer/stall.py` 用 `near_best_L` 判 stall=stop → 屬 route，不是收／升／退）。

## 3. 快撥 `quick.py`

`prepare(src, dest, *, state=None, L, epochs, clear_p=True) -> dict`
- `src` 是 `tree.json`（走 `import_.import_tree`，可帶 `state`）或一個樹目錄（`--from-root`：只複製基因體檔＋`ops.jsonl` 原樣含狀態，即 D11 的「保態原樹」；不複製 `epochs/ live/ tmp/ ledger.jsonl think1/ foundry/ RUN`，`ledger.jsonl` 寫空檔）。
- `dest` 必須在 `/home/lorkhan/code/playground-arc1/ws/evo/` 或 scratchpad `t2c/` 底下，且不存在或為空；否則報錯（防碰活樹）。
- 覆寫副本 `frozen.json.budgets.L=L`、`budgets.epochs=epochs`（`write_json` 格式）；原值記到 `quick.json.cfg.genome_budgets`（Argon 9：外框預算由快撥鎖死，塊 4 的 M1 只准突變內部配比，留給塊 4）。
- `clear_p`：副本 `truth/train/taskset.json` 的 `P` 改 `[]`，原 P 清單存到 `dest/../quarantine_P.json`（樹外）。
- 跑完 `check_root(dest)` 錯誤數記錄。

`run(dest, *, epochs, threads=4) -> quick.json`
- `threads` 上限 4，超過報錯。跑前、每 epoch 後查 `~/arcagi-STOP`（用 `run_tree` 的 `RUN` 檔機制：STOP 出現就刪副本的 `RUN`，不碰別處）。
- 呼叫 `epoch.run_tree(dest, "hammer", epochs=epochs, threads=threads, holdout=True)`；量 `wall_s`（整段 perf_counter）。
- 寫 `dest/../quick.json`：
```
{"schema":"think2-quick/1","genome_sha":…,"src":…,"state":bool,"cfg":{"L","epochs","threads","clear_p","genome_budgets"},
 "wall_s","auc_L","auc_speed_L","cost","eff","solved_L_final","logcost_L_final",   ← 取自 think1_meter.summarize
 "per_epoch":[…],                                                                   ← 同上
 "per_task":{"<L16 id>":{"solved":[epoch1..E 的 test_ok 0/1],"auc":int,"nodes_to_first":[…]}},
 "new_ops":[跑完 ops.jsonl 裡 id 不在起始 ops 的列 id],
 "guards":{"leak_new":"PASS|FAIL","leak_config":"PASS|FAIL"}}
```
 `per_task` 只收 L16，且 `Σ auc == auc_L`（寫 assert）。

## 4. 雜訊尺 `noise.py`（D16 成對 bootstrap）

`noise(dirs: list[Path], n_boot=1000, seed=0) -> dict`，每個 dir 有 `quick.json`。
- 決定論：所有 run 兩兩比 `auc_L`、`cost`、每題 `solved` 序列；`determinism_delta={"auc_L":max|Δ|,"cost":max|Δ|}`，`per_task_mismatch`＝至少一對不同的題數；`deterministic = 全 0`。
- 跑間散布：`sigma_run_auc_L`＝各 run `auc_L` 的母體標準差。
- 成對 bootstrap：對每一對 (i<j)，`d_t = auc_j(t) − auc_i(t)`（t∈L16 交集）；`random.Random(seed)` 有放回抽 |T| 題、算 Σd，重複 n_boot 次取標準差；`sigma_auc_L`＝所有對的最大值；另給 `mean_delta_auc_L`。全部 d=0 時 σ=0 並標 `"degenerate":true`。
- `compare(a, b)`：兩個不同樹的 quick 目錄 → `{"delta_auc_L","sigma_auc_L","z":delta/σ（σ=0 時 null）,"n_tasks_differ"}`。這是塊 4 拿來判顯著的介面。
- 寫 `noise.json`（`schema:"think2-noise/1"`，含 `n_boot`、`seed`、`runs`、上述欄位）。

## 5. 守門一 `guards.leak`（Argon 警告一、Argon 5）

`leak(target, *, forbid_root=活樹, base_ops=None) -> dict`
- `target`：樹目錄（讀 `ops.jsonl`、`truth/`）或 `tree.json`（＋可選 `state.json`）。
- 禁池＝`forbid_root` 的 `truth/train/taskset.json` P ∪ `truth/cal/ids.json` H8∪H24 ∪ target 自己的 P/H8/H24。（快撥副本 P 已清空，所以一定要從活樹取 P。）
- `config`：target 的 `truth/train/taskset.json` `P` 非空 → FAIL，理由寫「epoch.py:252 gate_ids=L16∪P、:335 shadow lp 含 P」。
- `violations`：每列 op 的 `payload.src_tasks` 與 `evidence.new_solves` ∩ 禁池，列 `{"op_id","field","tasks","pool":"P|H8|H24"}`；`tainted_ops`＝有違規的 op id。
- 給了 `base_ops`（起始 ops id 集）時，違規分 `inherited`／`new`；`leak_new`＝new 無違規才 PASS。
- 輸出 `{"rule":"no_build_from_P","config","violations","tainted_ops","inherited","new","leak_new","status"}`；`status`＝config PASS 且 violations 空才 PASS。

## 6. 守門二 `guards.thresholds`（Argon 警告二、Argon 6）

- 掃 `--scan` 目錄（預設 repo 的 `src/`、`scripts/`）下 `*.py`，正則 `pixel_acc|cell_acc|match_ratio|match_after|near_score|near_best|near_miss|_gradients`。
- 每個命中的 key＝`sha1(相對路徑 + "\n" + 該行 strip 後文字)[:12]`（**行級登錄**，同函式新增一行就是新 key，堵 Argon 6.1；行號不進 key，改上下行不失效）。
- 登錄表 `reports/think2-1109/guards/thresholds.json`：`{"schema":"think2-thresholds/1","entries":[{"key","file","text","metric","purpose":"rank|diag|route|accept|promote|retire","why"}]}`。
- FAIL：命中未登錄；或登錄 `purpose ∈ {accept,promote,retire}`；或 `purpose` 不在列舉內。登錄了但已不存在 → `stale`，只警告。
- `--init` 產草稿（purpose 由 sol 照程式語意填並寫 `why`，隊長審）。
