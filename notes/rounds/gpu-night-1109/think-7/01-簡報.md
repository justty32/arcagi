# think-7 01 簡報：GA 單步突變全中性之後，aos 樹的「學習」該往哪改

← [progress](progress.md)｜[02 fable](02-規劃-fable.md)｜[02b Argon](02b-Argon審.md)｜[代定清單](代定清單.md)

ELI5：樹的學習只有兩條管道——「記住哪些積木常用、下次先試」和「把常見片段包成新積木」。兩條在第一輪就把能學的學完了，之後每輪看到的是同一批答案，沒有新資訊。GA 又在改「學完的結果」（積木狀態、路由），而量尺每次會把這些結果剝掉、讓樹從零重學，所以突變被洗掉。要有增益，得改「學習規則」本身，讓 e1 之後還有新東西可學。

## 1. 量尺（不變，沿用 think-4 §8）

- 每題 b_e = log2(B_REF) − log2(min(ntf_e, B_REF))（train_ok 才計，否則 0；B_REF=40000 → 上限 15.29 bit）。`src/arcagi/treegen/meter_stats.py:40`。
- gain_bits = Σ_題 Σ_{e=1..4}(b_e − b_0)；base_bits = Σ b_0。`meter_stats.py:51-55`。
  → e1 的一次性改善會被乘 4；只在 e2 出現的改善乘 3，e4 才出現的只乘 1。
- 判定：親代 vs 變體逐題成對符號檢定＋Holm；健全門（raw verify、clone=親代、|no-learn-all gain|<1）。`meter_suite.py`、`meter_stats.compare`。
- 現值（t4c/t4f，L=40000、64 題、E=4）：親代 gain 168.7＝uses 順序 70.1＋comb 98.6；no-learn-all 0.0。

## 2. 為什麼學習只在 e0→e1（親代 run `ws/evo/meter/t4f-parent-g_*/root/epochs/*/status.json`）

| epoch | gate_in | lib_size | n_dormant | logcost_L |
|---|---|---|---|---|
| 0 | 14 | 0 | 0 | 898.6 |
| 1 | 20 | 1 | 0 | 870.3 |
| 2–4 | 20 | 1 | 2→5→8 | 872.1（不變） |

**(a) uses 通道一輪就飽和。** `epoch.py:317-321` 每輪把過 gate 的程式的運算子累加進 `state.uses`；`compress.order_from_uses` = log1p(uses)。e1 起 feed 恆為同 20 題 → uses_e ≈ e × u（同一組計數重複加），log1p 的排名不變、相對差距只微縮。順序先驗在 e1 定型，之後不帶新資訊。
**(b) comb 通道一輪就產完，而且只認「新解」。** sleep（`grow.py:sleep_ops`）從 feed 做 anti-unification，m=3/輪、與已有 comb 去重。feed 不變 → 候選只能越挑越差（saving 10→2）。judge（`judge.py:3-6, 42-47`）升 live 要 `new_solves` 或 witness hit：**只讓已解題變快（ntf 降）的 comb 永遠不升**。結果 11 條 comb 只有 1 條 live（`map(lam append $0 (reverse $0))`），其餘 TTL 到期 dormant。
  → **judge 與量尺目標錯位**：量尺 gain 的主體正是 ntf 下降（think-4 05 逐題表：17 題全是 ntf 變小，只 1 題 new_solve），judge 卻只獎勵新解。
**(c) 沒有新資訊來源。** L 題預算固定 40000（P 題才隨 epoch 成長，`pl.budget`）；e1 之後解集不變 → feed、uses、comb 候選三者全停。封閉迴路在 e1 到達不動點。

## 3. 為什麼單步突變對 64 題中性（g1′：9 標的、64 題每題 Δ=0）

**學習通道不在 genome 裡。** uses 存 `live/state.json`（不繼承、meter 每次重來），comb 會被 meter 剝掉（strip=all 全剝；targeted 剝 e0 直接用到的）再由 sleep 從同一 feed **決定論地重長出來**。所以：
- comb 狀態突變（t4f c0 刪 transpose comb、c1 改 dormant、c4 改 live）：被 strip 洗掉或被 sleep 重產 → 行為同親代。
- gate 參數（c2 loo_min_pairs 3→2、c3 retire_after 2→3）：只在「某 feed 題剛好跨門檻」時有效。量級：feed 20 題、64 題中受影響 ≈ 0；retire_after 只改 dormant 時點，被 dormant 的 comb 本來就不會升（§2b）→ 必中性。
- 路由（think-4 06：c3/c4）：被同 stall 下更高 priority 遮蔽，且 stall 永遠 ok。
**量級估算**：要讓一題 b 動，必須改變該題第一個命中程式的列舉位置。現行唯一能動列舉順序的是 uses（不在 genome）與 live lib（被重產為固定點）。可突變欄位中真正落在熱路徑、且會改變固定點的近乎沒有 → 單步突變的期望 |Δ| ≈ 0，與觀測 0/10 一致。這不是「GA 沒用」，是「GA 的搜尋空間不包含學習規則」。

## 4. 「直接改學習通道」假設（3–5 條，每條用現成量尺怎麼驗）

所有驗法都用同一把尺：64 題、L=40000、E=4、成對符號檢定＋Holm、親代 vs 變體；健全門照舊。**預期訊號形態**：變體的 b_2..b_4 > b_1（e1 之後仍漲），而非只有 e1 跳一次。

- **H1 judge 對齊量尺（speed-only 升級）**：comb 若在 shadow 讓共有已解題 ntf 總和下降 ≥ X（例如 Σlog2 ntf 降 ≥ 2 bit）且不擠出（no_crowd 已有），也可升 live。動 `judge.py:42` 的 hit 條件＋frozen.judge 新欄位。→ **改 hammer 原始碼**。
  驗：變體樹 vs 親代 gain_bits；副量尺 lib_size(e4) 應 >1、e2..e4 的 logcost_L 應繼續降。預期：目前 dormant 的 reverse／transpose／map-reverse 類（saving 6–10）至少 3 條升 live；think-4 05 顯示 transpose/reverse 類題 ntf 可再降 ×2–10。粗估 +20～+60 bit（純估，需量）。
- **H2 uses 換成「新資訊」計數（衰減/邊際）**：每輪只加「本輪新進 feed 的題」或改成按題去重（uses = 用到該運算子的不同題數，不跨 epoch 累加）。後者讓 e1..e4 的先驗完全一致（預期 gain 不變，當健全對照）；前者讓先驗聚焦新解題型。→ 改 `epoch.py:317-321`，**改 hammer 原始碼**。
  驗：gain_bits 不得下降（非劣），若加按題型分桶（見 H3）才期待正增益。
- **H3 uses 按題型分桶（條件先驗）**：依任務特徵（輸入輸出尺寸關係：同尺寸／放大／縮小等，已有 features 可用）分桶計 uses，enum 時用該題所屬桶的 order。e1 對「不同類」題不再互相稀釋（think-4 05：親代 lib 變大後純 primitive 題反小輸 0.2–14.7 bit）。→ 改 epoch.py＋arcbatch 需每題各自 order（body.py:227 已按 order 分批，可行），**改 hammer 原始碼**。
  驗：gain_bits 成對檢定；分解看「舊 no-learn 反小勝的 11 題」是否轉負。
- **H4 讓 e1 之後還有新資訊（預算重配不增總算力）**：已解題在 e≥1 用前一輪 ntf×2 當自身預算上限（反正會在 ntf 前停），省下的預算轉給未解題；總 evals_body 不得超過親代。新解 → 新 feed → uses／comb 都有新料。→ 改 `run_epoch` 的 budgets 行（epoch.py:276-277），**改 hammer 原始碼**；且 meter 的 L 定義需保持 40000 對 b 的計算（B_REF 不動）。
  驗：主量尺 gain_bits＋new_solves；**算力門**：Σevals_body 變體 ≤ 親代×1.05，否則判無效。
- **H5 GA 改搜「學習規則」而非「學到的狀態」（不改 hammer）**：genome 標的換成 gate_g1 的 m、k、max_holes、lib_cap、mdl_div（已在 ops 裡、hammer 會讀），撤掉 comb status／route／節點 weight。m=3→6 讓 sleep 每輪多產候選；max_holes 改變 anti-unification 粒度。
  驗：現成 GA＋meter 直接跑；先用 think-4 06 §4 建議的「round-trip 效果門」但門檻改成 **fixture 上 e2..e4 的 b 有變**（不是只 e0/e1）。注意：受 §2b judge 錯位限制，H5 單獨可能仍近零 → 這是對 H1 的前置對照。

## 5. 限制與已知風險

- B_REF=40000 ＝ L 預算，ntf 被截在 B_REF；新解題的 bit 上限 15.29×(E−e_解)。
- H1/H4 會讓 shadow/body 算力變化；量尺只算 ntf 不算 evals → 必加算力門。
- 只在 training 64 題選門檻；H24/H8 holdout 與 evaluation 只審計（frozen 規矩）。
- 判準要先登記（commit 雜湊）再跑；think-4 已有 prereg 格式（`reports/think4-1110/f/g1.json` 的 prereg_commit）。
