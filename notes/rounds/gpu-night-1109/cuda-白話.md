# CUDA 暴力搜尋雛形：白話進度（11-09 夜）

**做了什麼**：寫了一個 GPU 版的「候選程式評估器」`gpusearch`（`native/gpu/`）。它把一批簡單的格子變換（翻轉旋轉、放大縮小、鋪磚、裁邊、重力、填封閉區、左右疊合、換色……）排成長度 1～k 的所有組合，每支程式在題目的 train 範例上跑一遍，看輸出對不對（或補一張換色表就對）。同一套程式空間也用 CPU 版（直接用 arcbatch 自己的原語）跑一遍當對照。

**數字**：同一題組、同一空間下，GPU 每秒評估 0.7 億～3 億支候選，CPU（6 核）每秒 150 萬～285 萬支，**快 45～105 倍**（深度越深差越多）。212 題的解集合 GPU 跟 CPU 逐題完全一樣；抽 399 支 GPU 找到的程式交 Python 原版 DSL 跑，train 全對。顯卡同時被 LM Studio 佔用，數字是共用狀態下量的。

**整夜**：已在背景跑（systemd 單元 `arcagi-n2-overnight`）。先把 800 題全部搜到 5 步，再對主線還沒解、5 步內也沒解的題加深到 6 步、7 步（用「等價前綴去重」把重複的組合砍掉），06:00 自動寫彙總到 `reports/native-cuda-1109/overnight-summary.md`，列出找到的程式、哪些 test 也對、哪些是主線沒解過的新題。

**沒做**：S1 的 `forbid`（剪枝的是另一種程式語言，跟這次 GPU 這條不相依，留給 r10）；小網路排序器。
