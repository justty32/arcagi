1ARC 題目長什麼樣

ARC 是一套智力測驗，題目全是彩色方格圖。每題先給幾組「左邊的圖變成右邊的圖」當例子（叫練習對，train），再給一張新圖（考題，test），你要畫出它該變成什麼。

人看幾眼就懂規則，電腦卻很難，因為每題的規則都不一樣，沒辦法靠背。下面三題是資料夾裡的真題，點一下「看答案」對對看你猜得對不對。

計分規則（為什麼「答錯」和「不答」一樣）

每題每張考題只能交一個答案，一格不差才算對；一題有好幾張考題時要全部對才算這題對。答錯不扣分，所以「答錯」和「放棄不答」都是 0 分。

題庫分兩包，各 400 題：training（練習集）可以拿來調整方法；evaluation（考試集）規定不能看著調，是比較誠實的成績。

出處：docs/solvers.md「每個 test 只有一個預測」；src/arcagi/eval 計分 all(test["correct"] …)；gate-r08 README 的「回改＝看 evaluation 調參」。

2積木＋搜尋：我們怎麼解

想像一盒樂高。每塊積木是一個很小的圖形動作，例如「左右翻」「轉半圈」「把紅色換成藍色」「整張複製到右邊」。解一題，就是找出一串積木，把每一組例子的左圖都變成右圖。

電腦不會「看懂」，它的做法是硬試：先試一塊的，再試兩塊串起來的，越試越長。每串都拿去練習對上跑一遍，全部對上的才留下，最後拿它去變考題。

親手試一次

下面用題 A 的真資料，讓網頁自己把四塊積木一塊塊拿去套。每塊都在 3 組練習對上真的算一遍，結果不是寫死的。

為什麼會有「假解」

只有 2～4 組例子時，常常有好幾串積木都能把例子變對，其中有些只是湊巧，換到考題就錯。這種「練習全對、考試答錯」的叫假解。守門員（第 ③ 步）就是為了擋它而加的，第七輪加上後，練習集的假解從 57 題降到 20 題。

3兩套東西：解題器與錘子

文件常把兩套東西混著講，這是你跟不上的主因之一。它們目標不同，量分的方式也不同。

你在 11-09 晚上講過判準：要的是「能更快搜尋、更快解出題目的樹」，不是解題數。所以從第七輪起，主指標從考試集題數改成錘子的學習曲線，考試集只偶爾量一次。昨晚的工作大多是在右邊。

錘子怎麼「學」（兩條管道）

錘子目前只有兩條學習管道。第一條是「記住哪些積木常用，下次先試」，像整理工具箱把常用的放上層。第二條是「把常一起出現的幾塊包成一塊新積木」，叫 comb。

昨晚診斷出：兩條管道在第一輪就學完了，之後每輪看到同一批答案，沒有新東西可學。另外評審（judge）只在「解出新題」時才承認新積木，可是新積木的好處其實是「讓已經會解的題變快」，所以那些積木永遠升不上去，11 條只有 1 條轉正。

6瓶頸在哪

下面先擺事實（三組數字，都查過原檔），再擺主 agent 的解讀。

主 agent（fable）的看法 看法，不是定論

這三組數字指向同一件事：用現有積木組得出來的解，差不多都找到了。再加時間、挖更深、跑更快，只是在同一塊地上多挖幾遍。真正的瓶頸是「積木盒裡缺積木」，有些題需要的動作，盒子裡根本沒有。

示意圖，圈的大小不代表題數。

子 agent 查證時的補充：「時間 6.6 倍只多 2 題」這組數字，原報告的解讀是「搜尋空間太大、或積木不夠」兩者都有可能。加時間是線性的，組合數卻是爆炸性成長，所以它排除的是「多給一點時間」，沒有完全排除「聰明地少試很多」（剪枝、排序那種上百倍的省法）。昨晚試過的剪枝與排序器都很小、也都沒成，所以主 agent 的讀法目前最說得通，但還算不上證明。
三組數字分別量的是哪一盒積木

這三組不是同一盒積木量的：加時間是在主線解題器上，GPU 挖深用的是 GPU 版自己的一小套變換，蠟模的重現則是用錘子的 32 塊通用積木加 3 塊學到的積木。方向一致，但「缺哪些積木」要分開講是缺在哪一盒。

7蠟模漏斗：缺哪些積木的線索

「蠟模」是讓大模型（雲端的 GPT）寫一段逐步解題的小程式，每一步把圖變一點點。接著把每一步單獨丟給錘子，看它能不能用自己的積木重現那一步。這就像請老師示範解法，再看學生每一步跟不跟得上。

跟不上的那些步，正好就是「盒子裡缺的積木」的清單。主 agent 認為這是昨晚最值得追的東西。

兩件原本不知道的事

這 296 題是主線沒解的題嗎？不是，混在一起

挑題的程式只看「題目夠小」，不管主線解了沒。照題目特性表推算，296 題裡大約有 106～133 題主線早就解了。最後那 28 題「每步都重現得了」的，有 20 題主線本來就會，主線沒解的只有 8 題。

所以這 28 題大多是簡單題，不是新收穫。真正有用的是另外那 147 題「示範對了、但有步驟重現不了」，那裡才是缺積木的地方。

175 題的示範，拿去考題上對幾題？未知

不知道。鑄蠟模的程式只在練習對上驗，沒有拿去跑考題；整夜的原始紀錄留在 Linux 機上、沒進 git，這台電腦上查不到。

怎麼推出 106～133 與 20／8

挑題規則在 src/arcagi/llm/wax/runner.py 的 overnight_tasks()：16 題比較組，加上練習集中所有「練習對格子總數 ≤1200」的題，再扣掉錘子的保留盲測題（H8、H24）。這樣的小題共 323 題，其中主線已解 133 題（看 reports/task-features-1109/features.csv 的 mainline_solved）。扣掉的 27 題盲測題名單只在 Linux 機上，所以 296 題中主線已解的題數只能夾在 133−27＝106 到 133 之間。28 題的名單在 overnight-summary.md 裡，逐題對 features.csv 得 20 已解、8 未解（46442a0e、7fe24cdd、8d5021e8、beb8660c、caa06a1f、d10ecb37、e9afcf9a、eb281b96）。

「我們的積木」在這裡指錘子的 32 塊通用積木加 3 塊學到的積木，不是主線解題器那一大盒。wax-白話.md 也提到，空樹的小程式最多 4 個節點，連「把 8 換成 2」這種換色都寫不出來。

8今天要你決定的 5 題

今天早上你對晨報的 5 題回了「照推薦走」。之後主 agent 對第 1、3 題提出再議，所以這兩題還沒定案。另外三題照推薦。所有要動程式的部分，都要等回到有 GPU 的 Linux 機才施工。

第 1 題　准不准改錘子的評審，讓「已會的題變快」也算學到？再議中

原推薦：准。新規則預設關，舊行為一位元都不變；預期在量尺上多 8～25 bits。這是目前唯一被量尺證明有效的學習管道。

主 agent 的疑慮 看法

就算成功，題數大概也不會動。8～25 bits 攤到 64 題，大約每題快 1.1～1.3 倍，而昨晚時間給 6.6 倍才換 2 題。它有研究價值，能證明學習機制是通的，但不帶來分數。

子 agent 查證時看到的兩點，供你判斷

第一，錘子本來就不是交卷的那套（見第 3 節），改它的評審不會直接動到 147／56，這一點不需要靠估算。第二，你 11-09 晚上講過判準是「能更快搜尋、更快解出題目的樹，而非解題數」；照這個判準，「已會的題變快」正是你要的東西。要不要做，取決於你現在更在意哪一個。

關於「每題快 1.1～1.3 倍」：量尺的 bits 是把 4 輪加總的，如果平均攤到 64 題×4 輪，每題每輪只快約 1.02～1.07 倍；如果集中在少數題上，那幾題會快得多。主 agent 的估算是粗略量級。

第 2 題　演化（GA）這條線停不停？照推薦：停

停掉現在的演化回圈，框架留著。它突變的地方錘子根本不讀，在 64 題上反覆調參只會背題。等第 1 題改完、突變真的能影響錘子時再重看。

第 3 題　GPU 補位要不要預設打開？再議中

你的另一個專案與它的 agent。arcagi 的前提是「用 aos 體系（符號程式）解題」，大模型只負責找規則、寫程式，最後解題靠確定的程式。kb/README.md、kb/project/what.md
空樹／seed
錘子的起點：只有 32 塊通用積木、什麼都還沒學的樹。程式在 src/arcagi/seed/，第七輪打了標籤 r07-seed0。總表/輪次-r07-r09.md 第七輪
hammer（錘子）
會自己學的那棵樹，第九輪造好，活樹在 Linux 機的 ws/hammer。名字來自你的「先造一把 lv1 錘子，再用它打造 lv2 錘子」。總表/使用者方向.md 意見 5；r09/05-白話進度.md
gated（守門入口）
主線正式的解題入口 arcagi.solvers.gated，可疑的答案就放棄不答。147／56 都是它量的。gate-r07、gate-r08 README
假解
練習對全對、考題卻答錯的解，也就是湊巧或背答案。文件裡常寫成「過 train 答錯」。gpu-fallback-1110 README；gp-白話.md
補位
主線放棄的題，改用 GPU 窮舉找到的程式來答。開關叫 ARCAGI_GPU_FALLBACK，預設關。reports/gpu-fallback-1110/README.md
蠟模
大模型寫的逐步解題小程式。每一步再交給錘子的積木去重現，重現得了的步驟可以變成新積木的材料。gpu-night-1109/wax-白話.md
量尺
量「樹學得多快」的尺。把會學的樹和不學的對照組逐題比，用統計檢定判斷差距是不是真的。think-4/03-設計.md；think-7/01-簡報.md §1
bits
量尺的單位。每題看「找到第一個解之前試了幾個組合」，取對數；多 1 bit 大約等於少試一半。沒解出的題算 0，上限約 15 bits。think-7/01-簡報.md §1（B_REF＝40000）
epoch（輪）
錘子練一次的回合。每輪把練習題解一遍、記住常用積木、包新積木。think-7/01-簡報.md §2
comb
錘子從解法裡把常一起出現的幾塊積木包成的一塊新積木，要評審認可才會轉正。src/arcagi/hammer/grow.py、think-7/01-簡報.md
judge（評審）
錘子裡決定新積木能不能轉正的規則。目前只認「解出新題」，這就是第 1 題要改的地方。think-7/01-簡報.md §2(b)
GA（演化）
把錘子的設定當基因，隨機突變、留下表現好的，一代代改良。昨晚證實突變到的設定錘子沒在讀，所以零效果。晨報 結論 2；think-4
GP（遺傳程式）
在 GPU 上「先亂組一大堆程式，留下比較像的互相拼湊」的搜尋法，和一個個窮舉相對。昨晚結果是題數打平、更慢、多背答案。gpu-night-1109/gp-白話.md
