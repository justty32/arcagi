## 起

```sh
cd $A && env -u AOS_DAEMON -u AOS_KERNEL PYTHONDONTWRITEBYTECODE=1 AOS_LLM_KERNEL=$A/llm LITELLM_KEY="${LITELLM_KEY:-dummy-nonempty}" \
  systemd-run --user --scope --unit=arcagi-aos-daemon -p MemoryMax=16G \
  nice -n 19 aos-exec --stack $A/image $A/defs/root >>$A/root.log 2>&1
```

`--scope` 會佔住前景，交背景跑（Claude 用 run_in_background）。環境裡沒有 `LITELLM_KEY`，給非空假值即可（litellm 沒開驗證）；金鑰不寫進任何檔。

起好＝三台 ping 都回 `replied in … ms`（實測 52／202／51 ms，起後 1 秒內）：

```sh
for d in $A/image $A/llm $A/worker/.stack; do aos-daemon-ctl -d $d ping --timeout-s 30; done
```

## 開 agent（只讀）

```sh
export AOS_DAEMON=$A/worker/.stack PYTHONDONTWRITEBYTECODE=1; cd $A
aos-agent ctl add --name t1 --ws /home/lorkhan/repo/arcagi $A/defs/agent
aos-agent tools --target t1 add read $P/lib/base/read
aos-agent tools --target t1 add ls   $P/lib/base/ls
for t in wall_clock self_tools agents memory; do aos-agent tools --target t1 rm $t; done   # 範本預設工具全拿掉
aos-agent llm --target t1 set endpoint=luna
aos-agent tools --target t1 ls      # 應只剩 ls、read
```

範本 agent-fsm 預設帶 `self_tools`（改自己工具）、`agents`（生子 agent）、`memory`、`wall_clock`——最小權限要逐個 `tools rm`，回信的指令沒做這步。

## 問一題

```sh
aos-agent say --target t1 "讀 <相對 ws 的路徑>，列出…" && aos-agent listen --target t1 --timeout-s 600 > 答案.txt
```

listen 的 stderr 第一行是信件 id，stdout 是答案。下一題直接再 `say`（history 會累積；要乾淨就另開一隻 t2）。

## 帳在哪

- 對話全貌：`$A/worker/.stack/procs/t1/history.jsonl`
- 每次 think／tool 耗時與 token：`$A/worker/.stack/procs/t1/observed.jsonl`
- 總帳：`$A/llm/ledger.jsonl`（每封 elapsed_ms、usage）、`$A/llm/used.json`（當日各包呼叫數）

## 收工

- 只收一隻：先 `cp` 它的 history／observed 出來，再 `aos-agent ctl rm t1`（rm 會刪它整個 stack）。
- 整棵收：`kill -TERM 177262`（根 pid；先 `systemctl --user status arcagi-aos-daemon.scope` 確認）。根一層層往下收，agent 留成 `sleeping`；再跑一次「起」那行就醒回來。
- 不用 `systemctl --user stop`（會同時 TERM 全 scope，不是逐層收）——除非根已死、只剩孤兒。

## 看門狗怎麼盯

只盯根一個：`systemctl --user is-active arcagi-aos-daemon.scope` 或 `kill -0 <根 pid>`。總機、領班有 `auto_restart`，根會自己拉。根死了：

```sh
systemctl --user stop arcagi-aos-daemon.scope   # 清掉舊 scope 裡的孤兒（總機、領班 setsid，不隨根死）
# 再跑「起」那行；新根從 $A/image 接回 agent
```

不清舊 scope 直接起，同名 unit 會撞（回信推論，未實測）。

## 坑

- `AOS_LLM_KERNEL` 要在**根**的環境，不是下 `aos-agent` 的殼。
- `AOS_DAEMON` 起樹時一定 `env -u` 掉；開 agent 時反而要 export 成領班 stack。
- 不要在 arcagi 下直接 `aos-exec <agent 定義>`（會在 cwd 建 `.stack/`）。
- litellm 逾時 120 s → agent `stopped`；`aos-agent ctl start --target t1` 從原格接著寄。
- 到 200 次回 `BudgetMissing`，不自動降級。
- 寫入邊界實測：只 `.aos-run/` 有新檔；arcagi 其他處、aos repo、`~/.cache`／`~/.local`／`~/.config` 皆無 aos 寫入（詳 [結果.md](結果.md)）。
