## 1. 目標與使用者前提

- 使用者：拿 aos 體系（資料夾＝程式、node-pool 記帳分紅、covered 壓縮、元優化）解 ARC-AGI-1。**符號邏輯**；LLM 只找規則、寫程式、蒸餾；**神經網路盡量不用**；可吃 CPU、可寫 CUDA。方向問題不停線：隊長代定、記代定清單。
- 主軸不變（使用者歷次原話）：「**優化產生積木的過程**」（12:05）、「**用 aos 體系**」、「aos 函數或整顆樹本身也可以作為搜尋目標，優化這個優化的過程並且**持續遞迴嵌套**」（12:56）、「**子樹也是一種積木**」（13:13）。
- r04、r05 兩輪共同結論：**瓶頸在積木能表達什麼，不在怎麼搜**（加深 0 增量、原始碼空間鄰域改寫 evaluation 0 解；S1 把「物件原語不限第一步＋寬選擇器」走完寬樹就 +4）。

## 2. 不可違反的約束

| 約束 | 說明 |
|---|---|
| 成績以 **evaluation 400 題**為準 | training 有洩漏風險，只當開發集；**產生／評分積木只用 training**（含 S5 合成集，它只由 training 生） |
| 不用神經網路；**不新增 Python 依賴** | 純 stdlib；C++ 在 `native/`（S1 的領地） |
| 機器安全 | `nice -n 19`、單批 ≤16GB、顯存 ≤12GB、swap 512MB；**全機同時一條全量評測**，開跑前 `pgrep -af "arcagi eval"`；主線全量 `--workers ≤6`；≤50 題子集隨時可跑 |
| 額度緊 | 約 **3 條 opus 線×1 小時**；全量 training、evaluation **各一次**為原則 |
| 支線路徑不碰 | 主線不寫 `native/`、`src/arcagi/dsl/ext/`、`src/arcagi/llm/`、`aos/llm/`、`objrule/families/`、`docs/taxonomy/`、`scripts/synth_*`、`scripts/taxonomy_*`（[支線.md](../支線.md)）；可**唯讀呼叫**它們的產物 |
| 程式碼規矩 | `src/arcagi/<領域>/`，單檔 >300 行拆；pytest；退步列原因 |

## 3. 現況

## 4. 新證據：積木品質（S5 合成集，[reports/synth-s5](../../../reports/synth-s5/README.md)）

S5 用 re-arc 為 training 400 題各生 24 個合成 pair（`data_synth/`，5 秒重生）。拿現有 245 個產生積木的「在哪幾題成立」去合成 pair 上重驗：

| 種類 | 嚴格：24 個合成 pair 有一個不過 | 多數：8 份小樣本過不到一半 | 對照：原 test pair 不過 |
|---|---|---|---|
| formula | 34% | 13% | 1.6% |
| pred | **81%** | **50%** | 8.5% |
| extract | 61% | 44% | 13.7% |

- 白話：謂詞幾乎都在背答案（例 `size > 3` 這種門檻是照原題的小物件定的）；只多 1 個同分布 pair 看不出來——**原題範例太少**，合成集正好補這個。
- 三台產生器都已吃 `--data-root data_synth`（不用改程式）；硬換會丟 2 個帳上有收入的積木（`formula_0832d6a3`、`extract_f23ec080`），可能讓 evaluation 退步 → S5 建議**軟接**：分數＝原 train support 中「8 份小樣本過 ≥50%」的題數；有收入者不因合成集退休。

## 5. aos 那邊帶來的量法（arknights 第五輪，[28-帶去arcagi清單](../../../../simple_tools/aos/proto8/thinking/2026-11/07/arknights-kb/28-帶去arcagi清單.md)）

1. 元優化要**從空基準重跑**＋**兩條基準量雜訊**（arcagi 的枚舉是確定的，雜訊可能 0，但要量過才知道）。
2. 打基準前 **diff `aos/blocks/` 與 `aos/pool/`**：學到的積木會被快照進樹，「空基準」不空。
3. 教練學不動先查**真值供給**（arknights 第五輪 9% 改進幾乎全來自補真值）——對應這裡：產生器的評分料（原題 2～5 pair 太少 → 合成集）。
4. 新積木先**影子跑**、過門檻才上線；門檻開跑前先預核（用舊資料算能過幾條）。
5. 改進流程本身的花費另記 **meta 帳**（只記不分紅），算得出元優化回本沒。arknights 結論：主指標要選改進真的會動的量。
