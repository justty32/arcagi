## 2. 做了什麼（程式方法）

- **A 元優化＋合成集軟接**（`blocks/synth_score.py`、`blocks/meta/`、三台產生器 `--synth-root`）：積木在支持題的合成集 8 份小樣本過半才算 support；有帳收入的 5 顆豁免。`_gen/_meta` 擴到 extract＋formula，**雙折**（奇數挖偶數驗、再對調）、配對題級淨勝兩折皆 >0 才採用、主分＝淨邊際貢獻（扣背答案支持題）。結果：live extract 50→14、formula 35→19；采用 1 個 extract 設定（+4／+2），formula 全否定。meta 帳 `aos/meta/ledger.jsonl` 35 筆。
- **B 入口與量具**：正式入口＝`native/bin/solve`（Python 先跑、C++ 補、Python 重驗）；改寫搜尋預設關（`ARCAGI_REWRITE=1` 開、IoU 門控選項）；`scripts/attribution.py`（誰解、用哪些積木、Python／native 拆分）、`intercept.py`（Python 解出題也跑 C++ 量攔截）、`eval_r06.sh`。
- **C 影子工具**（`src/arcagi/shadow/`）＋`blocks/gen_llm.py`：S2 候選 37 顆過 11 入 `aos/blocks/llm_*`，單題巨集 6 顆改 covered；預核現有 186 顆產生積木只過 65。
- 帳 epoch 6（training）：96 顆 covered 退休；`llm_*` 參數開始分紅。

## 4. 得失

**得**
- evaluation 38→56、同大小 14→23，退步 0：表達力加寬（S1 `x_ray`／`x_compress`／`x_period`／`x_vrule`、S3 `bridge`／`stamp_key`／`halo8_key`）一次帶來 17 題——再次證明**瓶頸在表達力**。
- 量法第一次落地：雙折、淨邊際主分、meta 帳、影子門檻、歸因腳本；主線能說清「分數從哪來」。
- 合成集把背答案積木大量篩掉，evaluation 沒有因此退步（受豁免的 5 顆仍在出力）。

**失（否定結果）**
- 元優化在固定旋鈕上幾乎沒得調：formula 7 設定全 0 或負，extract 只 1 個設定雙折贏——**固定語法旋鈕觸頂**（Argon 預言的判準），要改結構（新原語、新組合）而不是調參數。
- 過 train 答錯上升：新原語帶大表（`stamp_key`、`x_vrule`）與 C++ 無投票；收不住就會吃掉泛化。
- S2 LLM 候選在 evaluation 0 解；training 2 題是自題自解。

## 5. 代定（摘要，全文 [代定清單](代定清單.md)）

照 fable 三線（D-r6-1）；元優化主分不跑求解器（D-r6-2）；S1 邊界：主線定入口與量法（D-r6-3）；Argon 採納雙折／淨邊際／消融／含 pred（D-r6-4）、改寫預設關＋攔截量測（D-r6-5）、線 C 允許 0 入庫（D-r6-6）、門檻 >42 並單列 Python（D-r6-7）；不採納呼叫鏈巨集（D-r6-8）；主線加 `n_holes`（D-r6-9）；LLM 直接解題不算主線分（D-r6-10）；`x_vrule` 受罰（D-r6-11）；單題 LLM 巨集 covered（D-r6-12）。

## 6. 下一輪方向（r07）

**主軸改為元優化**（使用者 14:55 原話）：「除此之外，我會希望arc agi這塊，把主要精力放在元優化。用於解決的訓練集只需要少少幾個就好，重點在於優化出能夠以最高效率最快解決問題的aos樹。途中可以繼續元優化這個元優化流程」。
**最終目標**（使用者 14:58 原話）：「arc agi的題目以2d為主，但aos的優化卻是偏向於程式流程。兩者都可以用符號迴歸配合llm，最終目標是能夠從零開始，在對目標題目(arcagi)完全無認知的情況下，配合無神經網路的優化器，成長到能夠解決問題」。
**產積木不經 LLM**（使用者原話）：「關於產出積木這件事，是否可以不經過llm？」→「可以」。

1. **主指標**：小 training 題組（5～20 題）從空基準學到解出的**學習曲線**（秒、節點、LLM 呼叫、輪數）；evaluation 只偶爾量泛化。改進對象＝aos 樹；元優化流程本身也可遞迴優化。r06 已有的料：空基準 blocks-root、`ARCAGI_POOL`、雙折、meta 帳、影子工具、歸因腳本。
2. **不經 LLM 產積木的候選**（aos 建議先 1、2）：(1) 原語拆細＋自組合（library learning、DreamCoder 壓縮）；(2) 從 vendor/re-arc 搬確定性程式當積木／原語來源（只覆蓋 training，用 evaluation 與合成集嚴防背答案）；(3) 程式自動診斷缺口（殘差分類取代 LLM 診斷）；(4) 演化式搜尋（帳本收益當適應度）。
3. **LLM 對照組基線**（S2，`reports/llm-s2b/README.md`）：eval20 test exact 7/20、誤判 0；r05 未解 training 40 題過 train 15、test 15；候選 73、live 8。
4. **S4 池子**（`reports/taxonomy-r04/README.md`）：畫線 92 解 5（射線／連線）、pattern 對稱週期修補 84、move 56（位移來自計數）、局部模板 halo／outline、crop＋summary 決勝順序（21 題過 train 答錯，最便宜）。
5. **收過 train 答錯**：C++ 結果加投票或最小支持度、`stamp_key` 大表與 `x_vrule` 限制；用 S5 合成集判。
6. **支線**：S2、S3 現任收；S1 轉速度，`x_*` 要包成 macro 才進 Python search（`PYTHON_SEARCH=False`）；新支線做元優化基建（M1 學習曲線量具、M2 樹變異／組合器、M3 meta 帳），路徑留 r07 設計。
