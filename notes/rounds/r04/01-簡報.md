## 1. 目標與使用者前提（原話整理）

- 使用者：「就是拿我們這套 aos 體系去嘗試解 arcagi」。**符號邏輯**解 ARC-AGI-1；LLM 只用來找規則、寫程式、蒸餾，最終解題靠確定的程式；**神經網路盡量不用**。可暴力吃 CPU、可寫 CUDA（RTX 5060 Ti 16GB）。
- 主軸（使用者 11-08 12:05 原話）：「試試看“優化產生積木”這件事。積木的本質是模式匹配，模式難道只有這些幾何嗎？一段程式輸出true,json object，也可以算模式對吧，或是一個公式如x=y的2次方，這樣甚至可以超越大小」。另一主軸：**用 aos 體系**（積木＝資料夾程式、node-pool 記帳、covered 壓縮、元優化）。
- 使用者也鼓勵**大量吃 CPU 的暴力搜尋**或 CUDA（在限制內）。目前全量評測只要一兩分鐘、每題最長 3.8 秒（預算 5 秒），算力遠未用滿。
- 方向問題不停線：隊長代定、記代定清單，使用者回來翻案。

## 2. 不可違反的約束

| 約束 | 說明 |
|---|---|
| 成績以 **evaluation 400 題**為準 | training 有 re-arc 現成解答（洩漏風險），只當開發集；**產生／評分積木只能用 training** |
| 不用神經網路；**不新增 Python 依賴** | 純 stdlib（無 numpy）。C++／CUDA 可另開子資料夾經 `--external` 接 |
| 機器安全 | CPU 批次 `nice -n 19`、≤12 worker、單批 ≤16GB、顯存 ≤12GB、swap 512MB；同時只跑一條全量評測 |
| 額度緊 | 本輪約 **3 條 opus 線×1 小時**＋全量 training、evaluation 各一次為原則；aos-llm 要額度 |
| aos repo **只讀** | 在 arcagi 的 `aos/` 試驗場做；不跑 install.sh |
| 程式碼規矩 | `src/arcagi/<領域>/`，單檔 >300 行拆（`blocks/pool.py` 302 行，本輪順手拆）；pytest；退步列原因 |
