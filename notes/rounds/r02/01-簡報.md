## 1. 目標與使用者前提（原話整理）

- 使用者：「就是拿我們這套 aos 體系去嘗試解 arcagi」。用**符號邏輯**解 ARC-AGI-1；LLM 只用來找規則、寫程式、蒸餾，最終解題靠確定的程式；**神經網路盡量不用**。可暴力吃 CPU、可寫 CUDA（RTX 5060 Ti 16GB）。
- 遠期：「arc agi 1 …是種子，後面會慢慢成長直到能完全代替 LLM 作爲思考驅動」「從聰明高階 LLM 蒸餾出智能種子，等到其成長到能自我吸收營養進行 RSI」。所以**能累積、能自我長大的結構**比一次性的分數更重要，但分數仍是量尺。
- **本輪新要求**（aos 轉達，11-08 11:45）：第一輪代定 D9（不用 aos 形式包裝）只當起步；**第二輪要開始把 aos 體系接進來**——例如積木／求解器做成 aos 的資料夾程式、蒸餾與積木記帳參考 aos 的 node-pool 與 kb-ideas 想法 20～22。怎麼接、接多少由你規劃決定。
- 方向問題不停線：隊長代定、記代定清單，使用者回來翻案。

## 2. 不可違反的約束

| 約束 | 說明 |
|---|---|
| 成績以 **evaluation 400 題**為準 | training 有 re-arc 現成解答（洩漏風險），只當開發集；不拿 evaluation 調參 |
| 不用神經網路；**不新增 Python 依賴** | 專案純 stdlib（無 numpy）。C++／CUDA 可另開子資料夾，經 `--external` 接 |
| 機器安全 | CPU 批次 `nice -n 19`、≤12 worker、單批 ≤16GB、顯存 ≤12GB、swap 512MB；同時只跑一條全量評測 |
| 額度緊 | 帳號 >85%：本輪要在**少量 agent 工時**內做完；全量評測整輪 training、evaluation 各一次為原則 |
| aos repo **只讀** | 要用 aos 程式就在 arcagi 底下建試驗場，用本機已裝的 aos 指令（見 §6），不跑 install.sh |
| 程式碼規矩 | 模組放 `src/arcagi/<領域>/`，單檔 >300 行拆；pytest；commit 附 evaluation 改前／改後題數；退步要列原因 |

## 3. 第一輪成果（已有，直接延用）

- 成績：**evaluation 21/400**、training 57/400（identity 0、template 0／6）；全量 evaluation 81 秒（純 Python 單程序，每題最長約 1 秒，**預算遠沒用完**）。
- 架構：`src/arcagi/dsl/` 18 個網格原語（registry 一筆一個：名字＋參數推斷函式＋實作）＋2 個終端學習器（換色表、鄰域規則表，不佔深度）；程式＝JSON 列表 `[["split_overlay","v","xor"],["colormap",[[10,3]]]]`；`solvers/search.py` 逐層 BFS 到 3 步、觀察等價去重、參數從範例推、最短程式勝出；中間網格可用標記色 10。
- 軌跡：`--traces` JSONL 已存 training／evaluation 每題的全部過 train 程式（≤30）與近失敗（≤20）——**library learning 的原料已在手**（artifacts/r01/，本機有）。
- 量具：`arcagi eval [--traces]`、`arcagi compare`（逐題對照、新增／退步、按題型分組）、`--external "cmd {input} {output} {trace}"` 跨語言。
