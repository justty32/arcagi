2像寄兩封信，語言不同也能合作

JSON 是大家都看得懂的資料信封。你的程式讀輸入檔，將預測寫到輸出檔；測試環境替你啟動程式和保存紀錄。印在終端的文字會成為 log，不會自動變成答案。

🏷️ tag：分類貼紙

例如「塗色」「旋轉」。同一題可以貼好幾張，由你自己分類，並非官方題型。

🎲 seed：亂數起點

像洗牌前先約好一個起點。程式要自己使用這個值，才能幫忙重現隨機步驟。

🎛️ params：設定小紙條

例如「最多找 100 次」。框架會送過去，由你的程式決定怎麼用。

要真正接程式，請看 檔案介面教學。命令使用 argv 陣列，設定的 cwd 和題目路徑以設定檔所在目錄為準。

3每塊積木都對，才算答對

我們採用 top-1：每個 test 只交一個答案。大小和每格顏色都一樣才通過；差一格也不算對。

標準答案

2002

✓ 全對

2002

✗ 差一格

2001

一題有兩張 test？

✓ ＋ ✓ → 整題成功
✓ ＋ ✗ → 整題未成功

同一題跑四次？

✓ ✗ ✗ ✗ → 成功率 25%

逾時、程式出錯，也算一次沒成功，不能偷偷拿掉。重複四次只有一次對，不會變成 100%。這是本地測試分數，不是官方私有測試成績。

4公平比較，就是每個方法跑同一份清單

把一次「某方法處理某題」想成一塊積木。我們的範例共有：

2 題 × 2 方法 × 2 seeds × 2 repeats ＝ 16 次

repeats 就是「相同設定再做幾遍」。要比不同方法，或同一方法的不同 params，給它們不同名字，放在同一份實驗設定。只測其中一題時，就剩下 8 次。

📒 results.json

完整實驗日記：哪題、哪個方法、seed、結果、錯誤、檔案放哪裡。適合程式再次分析。

📋 CSV

results.csv 一次執行一列；summary.csv 是彙總。適合試算表比較。

📊 report.html

直接看成功率圖、速度、單題矩陣和 tag 分組。平均與中位耗時都含失敗執行。

一題可有多個 tag，所以不同 tag 的統計可能重疊，不能加總成整份資料集。

5換你按下開始

先在 repo 根目錄打開終端。第一次使用，照 安裝步驟 準備 uv、依賴和題庫。以下命令不需要你先寫解法。

先跑完整範例

uv run arcagi experiment examples/experiment.json --output artifacts/first-experiment

預期 16 runs、0 errors。範例只做原樣複製和全零輸出，0 分很正常，代表你已會操作測試流程。

只跑一題／只跑一種自訂分類

uv run arcagi experiment examples/experiment.json --task 007bbfb7 --output artifacts/one-task
uv run arcagi experiment examples/experiment.json --tag fill --output artifacts/fill-tasks

這兩個命令各預期 8 runs、0 errors。輸出目錄必須是新的；重跑時換成 artifacts/one-task-v2，保留前一次結果。

跑完後用瀏覽器開 artifacts/first-experiment/report.html。若有錯誤，看結果裡的 artifact 目錄及 stderr.log；更多方法見 排錯教學。

6小測驗：你會當閱卷員了嗎？

這只是本頁的教學練習，不會執行真實 ARC 評測，也不會上傳答案。選了立刻看到原因，可以重選。

1. 大小相同，只有一格顏色不一樣，算答對嗎？

2. 同一題跑四次，只有一次全對，成功率是多少？

3. 哪一位需要拿到 test 標準答案？

4. 想再跑一次，輸出目錄已存在，該怎麼做？
