# 使用者新想法：把 aos 呼叫鏈當程式原始碼（$ref 折疊、借 janet/lua/python），像拉普拉斯變換到另一空間簡化

## 要你做什麼
使用者 11-08 午新想法（原話，照原文記進筆記，跟 12:56 那封「遞迴嵌套」合併成下一輪主軸）：
「除此之外，也可以把aos呼叫鏈抽象成程式原始碼，畢竟aos以json為基礎，甚至可以把細節折疊成指示詞$ref之類，這又跟我們的aos json,memory工具有所關係。也可以借用現有的程式語言如janet,lua,python等。這其實有點像拉普拉斯變換，將複雜運算丟到高維空間做簡化」

頂層白話理解（參考，非定案）：
- aos 的呼叫鏈（資料夾程式一層叫一層）本來就是 JSON，可以看成「程式原始碼」；重複的細節折成 `$ref` 指標（像函式呼叫／巨集），整條鏈就變短、可讀、可比對。你現在的積木 JSON S 式、巨集，就是這件事的雛形。
- 也可借現成語言當這個「原始碼」：本機有 janet（~/.local/bin/janet，Lisp 系、程式即資料最好變形）、lua／luajit、python3。在語言裡搜尋／改寫／模式匹配，比在一堆資料夾上做容易得多，做完再「變換回」aos 資料夾程式。
- 「拉普拉斯變換」的意思：把難的問題（在資料夾樹上搜尋與優化）先變換到另一個空間（程式原始碼／$ref 折疊後的 JSON），在那裡做簡單的運算（改寫、匹配、組合、遞迴優化），再變換回來。
- 參考：aos 的 $ref 與 JSON／memory 相關規範在 /home/lorkhan/repo/simple_tools/aos/proto8/docs/（grep `$ref`：CONCEPTS/01-設計理念/02-C-51.md、NORMS/05-基礎設施-窗/01-N-06～N-08.md、NORMS/10-基礎設施-定義與工作區.md、CONVENTION/03-shell版與inst版.md），唯讀。
怎麼落地由 fable 規劃（例如先做「積木程式 ⇄ janet 原始碼」雙向轉換，在 janet 上做改寫搜尋），記代定。
