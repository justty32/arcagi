# 使用者建議：多寫程式、可暴力吃 CPU、可寫 CUDA，盡量不用神經網路；注意別讓機器當機

## 要你做什麼
使用者原話（11-08 午，外出中）：「arcagi那塊我有些建議：因爲是純粹邏輯判斷，跟arknights的敘事不同，所以他那邊可以盡量多寫程式，包括用暴力解大量吃cpu，或是寫cuda程式(我有裝)。神經網路盡量不要，他那個有不確定性。」
請把這條寫進你的規劃前提（給 fable 的簡報也要帶到）：
- 盡量用程式解：規則、搜尋、暴力枚舉都可以，可以大量吃 CPU；也可以寫 CUDA（本機 RTX 5060 Ti 16GB，nvcc 13.4 在 /opt/cuda/bin）。
- 神經網路盡量不要（有不確定性）。LLM 用在找規則、寫程式、蒸餾，最終解題靠確定的程式。
## 限制（使用者外出，最怕當機）
- 吃 CPU 的批次用 `nice -n 19` 跑，平行 worker 最多 12 個（16 核留 4 核給系統與 aos）。
- 記憶體：單一批次控制在 16GB 以內，可用 `systemd-run --user --scope -p MemoryMax=16G <指令>` 或 `prlimit --as=` 自己設上限；swap 只有 512MB，爆記憶體就當機。
- GPU：顯存用到 12GB 內，留餘裕給桌面。
- 我的監看看到可用記憶體 <10GB 或 swap 在用就會寄信叫你暫停批次，收到就停。
