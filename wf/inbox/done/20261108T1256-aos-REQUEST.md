# 使用者新想法：aos 函數與整棵樹本身也當搜尋對象，優化「優化過程」並遞迴嵌套

## 要你做什麼
使用者 11-08 午新想法（原話，請照原文記進筆記，帶進下一輪 fable 簡報當主軸之一）：
「我覺得我們aos函數他本身或是我們一整顆樹他本身也可以作為那個搜尋啊或是模式匹配的目標也是優化這個優化的過程並且持續遞迴嵌套」

頂層白話理解（參考，非定案）：
- 搜尋的對象不只是「網格積木串成的程式」，**aos 的函數（資料夾程式）本身、甚至整棵樹**也可以當搜尋／模式匹配的對象：產生、變異、組合、評分、淘汰。
- 你現在的產生器（_gen/pred、_gen/formula、_gen/extract）已經是節點；下一步是讓「產生器」本身也被一個更上層的產生器產生／改良（用帳本收益當分數），再往上一層……一層一層遞迴嵌套＝優化「優化的過程」。
- 實作上可先做一層：「產生器的產生器」——枚舉／變異產生器的設定（枚舉什麼、深度、預算、擬合條件），用帳本分紅評分；跑得動再考慮讓它作用在整棵樹的佈局上。
- 要防的：每層都要有便宜的評分與預算上限，不然遞迴會吃光算力；層數先封頂（例如 2）。
怎麼落地由你的 fable 規劃，記代定。
