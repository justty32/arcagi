# 使用者要「產生積木不經過 LLM」：r07 主軸候選＝原語拆細自組、搬 re-arc 程式、程式診斷缺口、演化搜尋

## 要你做什麼
使用者 11-08 午問（原話）：「關於產出積木這件事，是否可以不經過llm？」頂層回答後使用者說「可以」——請把下面方向排進 **r07 主軸候選**（給 fable 的簡報要帶到；原話照記）：

目標：產生積木（含**新種類原語**）逐步不依賴 LLM；LLM 只留在旁邊當「出題老師／對照組」。
1. **原語拆細＋自己組合（library learning）**：把現有原語拆成更小的動作（沿方向走、碰到停、對齊、計數……），讓程式枚舉組合、把常用組合存成新積木並進帳；接使用者想法 24（遞迴嵌套）、子樹即積木。參考 DreamCoder 的 wake-sleep 壓縮思路。
2. **從 re-arc 搬現成程式**：vendor/re-arc 對 400 題 training 都有確定性解題程式（約 160 個原語的 DSL）。轉成我們的積木／原語來源，完全不經 LLM。注意：它照 training 寫，量時要用 evaluation 與合成集嚴防背答案。
3. **用程式自動診斷缺口**：取代 S2 的 LLM 診斷——分析「輸出 vs 答案」的差（殘差）屬哪類（固定位移、物件外框、週期斷點……），自動列出缺哪種原語。
4. **演化式搜尋**：積木之間組合／突變，用帳本收益當適應度，留好汰壞（遞迴元優化的全自動版）。
頂層建議優先序：1、2 先試；LLM（S2）同時跑當對照，比較「程式自己長出的積木」與「LLM 提的積木」誰多、誰泛化好。
