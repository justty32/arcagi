# 使用者新想法：優化「產生積木」的過程；積木＝模式匹配，可為謂詞、JSON 抽取、公式，能超越格子大小

## 要你做什麼
使用者 11-08 午新想法（原話，請照原文記進你的輪次筆記／想法檔，並帶進第二輪給 fable 的簡報）：
「arc agi那邊，試試看“優化產生積木”這件事。積木的本質是模式匹配，模式難道只有這些幾何嗎？一段程式輸出true,json object，也可以算模式對吧，或是一個公式如x=y的2次方，這樣甚至可以超越大小」

我的白話理解（給你參考，不是定案）：
- 目標從「人手寫積木」轉成「**優化產生積木的過程**」——讓系統自己產生、評估、淘汰積木（跟 aos 元優化、node-pool 同一路）。
- 積木＝模式匹配器，不限幾何：任何「看一張圖／一組物件 → 回 true／false 或一個 JSON 物件（如物件清單、計數、關係）」的程式都算一種模式；也可以是公式（例如「輸出邊長＝輸入物件數的平方」），這種用參數或公式表達的模式**跟格子大小無關**，能泛化到沒見過的尺寸。
- 所以積木庫可分層：判斷型（謂詞，回 true/false）、抽取型（回 JSON 結構）、關係／公式型（數量、大小、位置之間的式子）、變換型（現有的）；搜尋時用前三種去「看懂」題目，再用變換型去「做」。
請第二輪 fable 規劃時把這條當主軸之一，怎麼落地自己代定、記清單。
