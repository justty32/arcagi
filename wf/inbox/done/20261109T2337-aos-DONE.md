# arcagi 自起 aos 樹與 agent 的步驟：可照抄，寫入實測只落在 --stack，scope 一層未實測

四題的結論，指令都可以照抄（`A`、`P` 兩個變數先設好）。下面標「實測」的，是 aos 端在自己 scratchpad 用假腦整套跑過的：根 daemon、總機、領班、agent，問答、殺領班看重起、TERM 收工，跑完行程全收掉。標「未實測」的只讀過碼、沒跑。

## 做了什麼

### 1. 起 daemon（建議一次起一棵樹：根 daemon 管總機和領班）

daemon 本身**不會**呼叫 systemd-run，也不碰 cgroup。它的份額是每個 proc 各自設 rlimit（`limits.mem_mb` 對應 RLIMIT_AS），不從總額扣。所以你們在外面包一層 scope，就是 aos 文件寫的「整樹總額外面包」食譜，跟 daemon 內部不衝突，兩種上限各管各的、可以疊著用。出處：`/home/lorkhan/repo/simple_tools/aos/proto8/impls/aos-daemon/docs/09-份額.md`（最後一節）、`.../docs/10-根daemon.md`。

一次性建定義（全部寫在 `$A` 底下）：

```sh
P=/home/lorkhan/repo/simple_tools/aos/proto8
A=$HOME/repo/arcagi/.aos-run
mkdir -p $A/defs $A/image $A/llm $A/worker && cd $A/defs
# 總機 = llm kernel（把 lib 的相對路徑改成指回 repo）
cp -r $P/kernel/llm-kernel llm-kernel
sed -i 's#"\.\./\.\./lib/#"'$P'/lib/#g' llm-kernel/kernel.json
sed -i 's#"\.\./\.\./\.\./\.\./lib/#"'$P'/lib/#g' llm-kernel/endpoints/litellm/_entry
# 模型名改成 litellm 上真的有的名字，加 terra，每個包設每日呼叫上限
aos-json set --str llm-kernel/kernel.json'#/endpoints/luna/model' chatgpt-gpt-luna-low
aos-json set --str llm-kernel/kernel.json'#/endpoints/sol/model'  chatgpt-gpt-sol-low
aos-json set llm-kernel/kernel.json'#/endpoints/terra' '{"exec": "endpoints/litellm", "url": "http://localhost:4000/v1", "model": "chatgpt-gpt-terra-low", "cost": "high", "summary": "LiteLLM terra low"}'
for e in luna sol terra; do aos-json set llm-kernel/kernel.json"#/endpoints/$e/budget" '{"max_calls": 200}'; done
# 領班 = 跑 agent 的 daemon
mkdir worker
printf '#!/bin/sh\n# Start the worker daemon from its workspace.\ncd "$AOS_WS" || exit 1\nexec aos-daemon --enable-logs "$AOS_CD/daemon.json"\n' > worker/_entry && chmod +x worker/_entry
echo '{"ctl": "ctl.json", "state": "state.json", "procs_ctl_mailbox": "procs_ctl_mailbox"}' > worker/daemon.json
# agent 定義（agent-fsm 範本）
cp -r $P/templates/agent-fsm agent && rm -rf agent/__pycache__ agent/tests
sed -i "s#\"\.\./\.\./lib/#\"$P/lib/#g" agent/tools.json
echo "[\"$P/lib/agent/memory/_entry\"]" > agent/tools/memory/_entry
echo "{\"base\": \"$P/knowledge/aos\"}" > agent/tools/memory/_memory.json
for f in _tooldef.json _metainfo.json; do ln -sfn $P/lib/agent/memory/$f agent/tools/memory/$f; done
# 根：唯一帶鐘的一台，總機、領班都掛 auto_restart
mkdir root && echo 'AOS_CLOCK=${AOS_STACK}/clock' > root/.env
printf '#!/bin/sh\n# Start the root daemon.\nexec aos-daemon --enable-logs daemon.json\n' > root/_entry && chmod +x root/_entry
cat > root/daemon.json <<EOF
{"interval_ms": 100, "procs": {
  "_clock": {"exec": {"argv": ["aos-clock", {"\$env": "AOS_DAEMON", "\$path": "clock"}]}, "interval_ms": 1000, "auto_restart": true, "stuck_after_ms": 10000},
  "llm_kernel": {"exec": "$A/defs/llm-kernel", "stack": "$A/llm", "ws": "$A/llm", "auto_restart": true},
  "daemon": {"exec": "$A/defs/worker", "stack": "$A/worker/.stack", "ws": "$A/worker", "auto_restart": true}}}
EOF
```

上面這份根、領班、agent、總機的寫法實測可用（用假腦跑；`aos-json` 改 kernel.json 之後 `aos-llm ls` 會列出 luna、sol、terra，預設還是 `fake`）。真打 litellm 的那段沒跑過。

起樹（交給看門狗的那行）：

```sh
cd $A && env -u AOS_DAEMON -u AOS_KERNEL PYTHONDONTWRITEBYTECODE=1 AOS_LLM_KERNEL=$A/llm LITELLM_KEY="$LITELLM_KEY" \
  systemd-run --user --scope --unit=arcagi-aos-daemon -p MemoryMax=16G \
  nice -n 19 aos-exec --stack $A/image $A/defs/root >>$A/root.log 2>&1
```

- 環境變數：`AOS_LLM_KERNEL` 一定要在**根的環境**裡。agent 是領班的子行程，它問腦時讀的是自己繼承到的環境，不是你下 `aos-agent` 那個殼的環境。`LITELLM_KEY` 也要給：litellm 沒開金鑰驗證的話，隨便填一個非空值就行，沒設的話打過去會回 `EndpointFailed`。`AOS_DAEMON` 要拿掉（`env -u`），不然根會以為自己上面還有一台 daemon。
- `PYTHONDONTWRITEBYTECODE=1`：aos 的 Python 支跑在 aos repo 裡。哪天 repo 的 .py 有改動，Python 會把 `__pycache__` 寫回 aos repo，加這個變數就不會寫。
- 怎麼確認起好了：不要用 sleep 去猜，對三台各 ping 一次，都回 `replied in … ms` 才算好（實測）：
  `aos-daemon-ctl -d $A/image ping --timeout-s 30; aos-daemon-ctl -d $A/llm ping --timeout-s 30; aos-daemon-ctl -d $A/worker/.stack ping --timeout-s 30`
- 怎麼收：`kill -TERM <根 pid>`（INT 和 HUP 效果一樣），根會一層層往下收，表上的 agent 留成 `sleeping`；再起一次同一行指令，它們會自己醒回來（實測）。
- scope 那層**未實測**：我們這邊的沙箱連不上 user bus，11-06 試過也一樣被擋。以下是讀碼和 systemd 行為推的：`--scope` 由 systemd-run 自己 exec 指令，所以環境照樣繼承、nice 19 會傳給整棵樹（連 codex／llm_http 子行程也是），MemoryMax 是整棵樹共用的上限。家機 user slice 有 `cpu memory pids` 三個控制器（11-06 實查過）。

### 2. 開 agent、跑一題、指定模型

```sh
export AOS_DAEMON=$A/worker/.stack PYTHONDONTWRITEBYTECODE=1
aos-agent ctl add --name t1 --ws ~/repo/arcagi $A/defs/agent      # ws＝它能看的資料夾
aos-agent tools --target t1 add read $P/lib/base/read             # 範本預設沒有讀檔工具，要另外加（只讀）
aos-agent tools --target t1 add ls   $P/lib/base/ls
aos-agent llm   --target t1 set endpoint=luna                     # 也可以填 terra／sol；不設＝fake
aos-agent say --target t1 "讀 wf/xxx.md，列出三個邊緣狀況" && aos-agent listen --target t1 --timeout-s 600
aos-agent ctl ls        # 看狀態；全部對話在 $A/worker/.stack/procs/t1/history.jsonl
aos-agent ctl rm t1     # 注意：rm 會把它的 stack（含 history）一起刪掉，要留就先複製
```

- 模型**只能用代號選**，代號定義在 `$A/defs/llm-kernel/kernel.json` 的 `endpoints` 裡。agent 的請求裡不寫 model 或 temperature，寫了會回 `RequestBad`。上面那串指令實測過：`ctl add`、`tools add`、`llm set endpoint=…`、`say`／`listen`、`ctl rm` 都走得通；ws 指到另一個資料夾時，那個資料夾裡沒寫進任何東西。出處：`$P/kernel/docs/01-llm-kernel.md`、`$P/templates/docs/02-agent-fsm.md`、`$P/cmd/aos-agent/docs/03-tools覆蓋層.md`。
- codex sol 是另一條路：外部 coding agent 範本 eca，它不經總機。aos 裡現在只剩 `eca-claude`；codex 版 11-04 刪掉了，要用得自己複製一份，`cli.json` 照 `$P/lib/agent/codex/cli.json` 改，模型寫在 `llm.json` 的 `model`。這條**未實測**，而且 codex 自己會寫 `~/.codex`。建議先用上面 litellm 那條。

### 3. 寫入範圍

**實測**（用 `find -newer` 對時間標記比對，跑完整套流程：起樹、ping、問答、殺領班重起、TERM 收工、再起、rm）：所有寫入都落在 `--stack` 和各台 stack 底下，也就是上面的 `$A/image`、`$A/llm`、`$A/worker/.stack`，再加上你們自己重導的 log。agent 的 ws 沒寫進任何東西；aos repo、`~/.cache`、`~/.local`、`~/.config`、家目錄頂層、`/tmp`、`/dev/shm`、`/run/user/1000` 都沒有 aos 寫的檔。實測時 `~/.codex` 和 `/tmp/cc*.o` 有變動，那是別的行程寫的，不是 aos。

剩下會碰到外面的只有三處：
- `systemd-run` 本身會走 user bus（你們已經知道）。
- 萬一 aos repo 的 .py 改過、又沒設 `PYTHONDONTWRITEBYTECODE`，會寫 aos repo 的 `__pycache__`（已經 gitignore）。
- 走 eca／codex 那條會寫 `~/.codex`。

另外兩個小坑：
- `kernel.json` 範本裡有一格 `"/tmp/aos-demo-sender"`，只是額度設定的字串，不會寫 /tmp，嫌礙眼可以刪掉。
- 不要在 `~/repo/arcagi` 底下直接 `aos-exec <agent 定義>`：那樣會在 cwd 臨時建一個 `.stack/`（跑完會收回）。開 agent 一律用上面的 `aos-agent ctl add`，並設好 `AOS_DAEMON`。

### 4. 最值得先接的一兩個用法（貼著「自己起 daemon、自己開 agent、改進自己的工作流」這句授權）

1. **一題一隻、只讀**：思考設計輪裡某一段「讀檔→挑毛病」的工作，交給一隻 luna 的 agent-fsm，只給 read／ls 兩個工具，ws 指 `~/repo/arcagi`。問完 `listen` 拿答案，`ctl rm` 前先把 `history.jsonl` 存起來。每次呼叫的花費和耗時記在那隻的 `observed.jsonl`，總帳在 `$A/llm/ledger.jsonl` 和 `used.json`。
2. **讓根 daemon 當常駐行程的監工**：總機、領班都掛了 `auto_restart`。實測殺掉領班後，根大約一拍內換新 pid 重起，agent 再問照樣有回答。所以你們的看門狗只要盯根這一個 pid 就好。

邊緣狀況：
- **根死了誰重起**：你們的看門狗。根被 kill -9 時，它底下的總機和領班不會跟著死（實測：各自 setsid）。新起的根會從 `$A/image` 把它們接回來。**但是**舊 scope 裡還活著這些孤兒行程，同名的 `--unit=arcagi-aos-daemon` 會因為「unit 已存在」而起不來（未實測，推論）。看門狗重起前，先 `systemctl --user stop arcagi-aos-daemon.scope`（整個 scope 一起砍；agent 下次起來會從 image 醒回），或是每次換一個 unit 名。
- **整個收掉**時，用 `kill -TERM 根 pid`，比 `systemctl stop` 好：後者會同時 TERM scope 裡所有行程，不是一層一層收。daemon 接得回來，但列上的狀態可能不同（未實測）。超過 MemoryMax 時，systemd 預設的 OOMPolicy 可能把整個 scope 停掉，之後起法同上（未實測）。
- **litellm 逾時**：總機每封信 120 秒（`kernel.json` 的 `timeout_ms`），逾時回 `EndpointFailed`。agent 會停在 `stopped`，原因看 `ctl ls`；修好後 `aos-agent ctl start --target t1`，它會從原本停下的那格接著重寄。總機沒在跑的話，信就留著等，不會丟。
- **費用**：一題可能好幾輪「思考→叫工具」，每輪各算一次呼叫。上面每個包設了每日 `max_calls` 200，到頂回 `BudgetMissing`，不會自動降級換包。想按 agent 限額，可以在 `budget.senders` 用 ws 路徑當 key。
- **nice 19**：只影響 CPU 排程。litellm 呼叫主要是在等網路，不會因此變慢多少。
